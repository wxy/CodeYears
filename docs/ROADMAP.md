## P1 · 数据、身份缓存与性能可行性

状态：PR #1–#19 均已合入；P1-B 单账户真实 Chrome 缓存主流程及跨年修复检查通过。本机 Metal 六组工程原型在 60 Hz 内建屏幕约 60 FPS，暂停/静止及可观察释放已有证据；真实后台、身份矩阵和 Edge 仍待验收。P1-G 尚未整体通过，详见 [进度报告](reports/P1-G-READINESS.md) 与 [60 Hz 补充](reports/P1-G-60HZ.md)。按用户先看可视化的要求，风景体验与剩余门槛并行推进，不把原型交付写成完整阶段通过。

按以下顺序收敛风险；渲染模拟数据原型可在真实数据采集结果尚未完成时独立验证，但两者结论必须分开。

1. **无 Token 同源获取与解析**：验证真实登录/退出状态的指定年份响应、每日数量来源、日期覆盖和年度合计。
2. **访问者身份与本地年度缓存**：验证 A/B/退出登录、身份不明、请求中切换、多标签页、权限可见性变化、刷新和清除。
3. **20 年 3D 性能原型**：用确定性 7,305 天数据分别验证 City 与 Terrain 的按需加载、播放、静止、后台、关闭与页面交互影响。

验收门槛：

- [ ] [D1–D6](DATA_AND_PRIVACY.md) 有真实 Chrome / Edge 证据；逐日数据与统计差异有结论。
- [ ] 身份隔离无跨作用域读写；旧请求不能污染新身份；缓存失败与取消路径可用。
- [ ] 选定最小权限，记录安装提示、请求/资源环境与原页面导航行为。
- [ ] 两类渲染在具体设备上满足记录的预算，静止与离开资源约束有证据。
- [ ] 报告区分通过、失败、未验证；清理临时产物。

若拿不到可靠真实数量，停止将数据标为准确，先定位来源；若身份不能可靠识别，关闭缓存复用；若性能不足，降低复杂度。不能擅自增加 Token、后端、估算数量或网站绕过问题。需要改变产品约束时再确认具体方案。
