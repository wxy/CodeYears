## 本轮交付

由用户在 GitHub 个人主页主动打开扩展，注入 Shadow DOM 诊断面板；选择一年后才执行该年的同源请求。解析真实日期与绑定 tooltip 的数量，对比页面年度总数；提供取消、错误和关闭反馈。只使用内存，不实现 P1-B 缓存或正式 3D 视图。

实际页面观察：日期来自 `data-date`，数量来自 `tool-tip[for]` 与日期格 ID 的绑定。当前观察到英文数量文本；未识别的语言/格式须明确失败。请求 URL 与 `X-Requested-With` 来自本轮网页观察和验证，不是稳定 API。

## 直接验证路径

成功路径覆盖真实历史年度（含闰年）、当年已发生日期、日期数量和年度合计；对照本人及另一个公开主页。必要失败/取消路径覆盖非个人主页、无效输入、网络失败、取消与关闭。登录切换和私有贡献证据按实际可观察范围记录，不退出用户现有登录或复制凭证。

解析失败方式：日历/tooltip 缺失、日期非法或重复、日期范围不完整、数量/语言不支持、年度标题不符及合计不一致，均不得填零或显示为成功。网络 HTTP 错误、重定向和取消分别报告。

## 运行

`npm run build` 后在 Chrome/Edge 扩展管理页加载 `dist/`。在 GitHub 个人主页点击扩展图标，再点击“打开数据诊断”，按面板选择年份。开发时 `npm run dev` 监听两个构建入口；更新后重新加载扩展。

检查与构建可以指定 `npm run build -- --outDir <系统临时目录>/dist`。实际结果与未完成范围记录在 `docs/reports/P1-A-DATA-PROBE.md`；原始响应、截图、日志和测试构建不进入 Git。
