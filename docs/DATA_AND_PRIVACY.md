# 数据与隐私

状态：P1-A 请求与解析诊断原型已实现，缓存尚未实现；实装与数据结论见任务报告。更新日期：2026-10-30。

## 已确认原则

- 不索取 GitHub Token、不新建登录、不建设后端；利用访问者已有 GitHub 会话。
- 同源贡献页面分年获取真实每日数量；不根据绿色深浅或 `data-level` 推算。
- 数据只在本机按年份缓存；区分登录访问者和正在查看的主页所有者。
- 不读取、保存或导出会话 Cookie、Token、仓库详情或其他无关页面内容。
- 不加入遥测、广告或第三方分析。真实页面响应和用户缓存不进入 Git。

项目希望复用现有会话，不代表已经验证所有浏览器环境、SSO 或可见性场景。

## 请求与解析验证清单

2026-10-30 已在真实 Chrome、英文页面及访问者 `wxy` 下验证本人 2024/2026 和他人 2025 年的获取、解析、覆盖、合计，以及取消/断网/关闭路径。实际样本与限制见 [P1-A 报告](reports/P1-A-DATA-PROBE.md)。以下是完整验收标准，尚未全部满足；Edge、语言及身份可见性矩阵仍待验证。

| 编号 | 问题 | 通过依据 |
| --- | --- | --- |
| D1 | 现有会话的同源请求是否能取得指定年份数据 | 在真实 Chrome / Edge 中记录请求来源、参数、状态、响应形式与会话状态 |
| D2 | 数量是否真实且可准确解析 | 与页面日期详情逐日对照，覆盖零、非零、大数及不同语言；不取颜色等级 |
| D3 | 日期覆盖是否正确 | 跨年、闰年、历史年份、当年未结束；排除日历填充格，不把未来或缺失日期当成零 |
| D4 | 年度合计能否与页面一致 | 同一访问者、同一页面范围逐日合计对照；不一致时解释时间范围或统计口径，未解释前不标通过 |
| D5 | 非正常响应如何处理 | 断网、登录页重定向、403/429、取消与页面结构变化明确失败；不缓存空数据为成功 |
| D6 | 数据可见性是否随身份变化 | 本人、他人、退出登录及私有贡献显示变化分别对照，记录允许看到的数量范围 |

当前原型根据本轮真实响应选择 `data-date` 与 `tool-tip[for]` 解析英文数量；年度请求路径及 HTML 属性不是稳定 API。本轮成功样本不能证明接口长期稳定或私有贡献可见性完整。

GitHub 的官方说明区分公开与私有贡献的可见性：[Contributions on your profile](https://docs.github.com/en/account-and-profile/concepts/contributions-on-your-profile)。这不能证明某个网页解析器能取得所有贡献，也不能保证逐日与年度统计在任意范围自动一致。

## 访问者隔离

缓存作用域至少包含：结构版本、已确认的访问者身份（已登录账户 / 已确认未登录）、主页所有者、年份。账户名的规范化和身份来源需实测。

- 主页路径 `/someone` 只能说明被查看者，不能说明访问者。
- 无法确认访问者身份时不读取或写入贡献缓存，不把“身份不明”当作“未登录”。
- 发起请求时捕获身份作用域；写入前重新确认该作用域仍有效。切换账户或退出后取消旧请求，不能将旧响应写进新身份缓存。
- A 看同一主页、B 看同一主页、退出后看同一主页，应使用隔离的数据与请求结果；不能仅按“主页 + 年份”查缓存。
- 同一访问者的 SSO、组织权限或私有贡献可见性也可能变化，身份键本身不能保证缓存永远有效。刷新与失效策略需经验证。

多标签页切换身份的检测能力、隐身窗口行为和本地存储共享范围都是 P1 验证项。缓存隔离主要防止应用错误展示，不等同于对拥有本机或浏览器资料访问权的人加密保护。

## 年度缓存计划

候选记录包含：作用域、日期/数量、抓取时间、结构版本、解析器版本和覆盖状态。`src/cache/types.ts` 仅是初始契约；TTL、容量上限、淘汰方式及存储 API 尚待实测。

- 历史年份可复用，但不能宣称永久不变；当年需要刷新。
- 缺失、解析失败或身份不明不覆盖已有的有效记录。
- 不长期保存原始 HTML；仅保留所需日期/数量和最小来源元信息。
- 实现清除本地数据与手动刷新的可理解入口；具体 UI 在后续 MVP 中确定。
- 存储额度、写入失败、结构升级和损坏记录需要直接路径验证。不能用 `unlimitedStorage` 掩盖未测容量问题。

## 权限待验证

当前 P1-A 使用 `activeTab` 与 `scripting`：主动点击后在当前 GitHub 主页临时注入本地诊断脚本，用户选年份后才同源请求。未申请 Cookie、存储或持久 host permissions；未自动注入页面。此选择尚不能代替 Chrome / Edge 完整产品权限验收。以下是后续候选，尚非发布清单：

| 能力 | 候选方案 | 待验证点 |
| --- | --- | --- |
| 主页入口与同源请求 | 仅 GitHub 范围 content script | 匹配范围、同源会话、站内导航和注入时机 |
| 年度本地缓存 | `chrome.storage.local` 等本地介质 | 所需权限、额度、身份作用域与清除行为 |
| 拆包资源加载 | 扩展本地资源及必要的 web accessible resources | 实际加载环境、允许源和最小公开资源范围 |

不提前申请 `cookies`、`<all_urls>` 或宽泛网站访问。是否需要 `host_permissions`、`activeTab`、`scripting` 等，必须由选定的注入/请求路径证明；不能宣称无 Token 就必然不需要权限，也不能宣称当前清单可支撑完整产品。

## 发布前验收

在真实 Chrome 与 Edge 分别验证 D1–D6、A/B/退出登录隔离、请求进行中身份切换、多标签页和刷新失效；确认安装提示、可访问页面范围、本地清除和最终隐私说明。仅记录脱敏报告，清理临时页面、响应、截图和缓存。当前仅 P1-A 报告所列 Chrome 直接路径通过，完整数据与隐私验收尚未通过。
