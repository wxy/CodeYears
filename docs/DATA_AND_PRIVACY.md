## 已确认原则

- 不索取 GitHub Token、不新建登录、不建设后端；利用访问者已有 GitHub 会话。
- 同源贡献页面分年获取真实每日数量；不根据绿色深浅或 `data-level` 推算。
- 数据只在本机按年份缓存；区分登录访问者和正在查看的主页所有者。
- 不读取、保存或导出会话 Cookie、Token、仓库文件、PR正文及无关页面内容；用户主动悬停的活动摘要仅按上述最小范围在页内使用。
- 不加入遥测、广告或第三方分析。真实页面响应和用户缓存不进入 Git。

项目希望复用现有会话，不代表已经验证所有浏览器环境、SSO 或可见性场景。

## 访问者隔离

当前缓存键包含 schema 1、已确认访问者（登录名 / 已确认未登录）、主页所有者和年份；账户名及主页名按 GitHub 的大小写不敏感形式转为小写。缓存记录保存同一作用域、解析器版本和抓取时间。真实账户名/身份源仍需实装验证。

- 主页路径 `/someone` 只能说明被查看者，不能说明访问者。
- 无法确认访问者身份时不读取或写入贡献缓存，不把“身份不明”当作“未登录”。
- 发起请求时捕获身份作用域；写入前重新确认该作用域仍有效。切换账户或退出后取消旧请求，不能将旧响应写进新身份缓存。
- A 看同一主页、B 看同一主页、退出后看同一主页，应使用隔离的数据与请求结果；不能仅按“主页 + 年份”查缓存。
- 同一访问者的 SSO、组织权限或私有贡献可见性也可能变化，身份键本身不能保证缓存永远有效。刷新与失效策略需经验证。

多标签页切换身份的检测能力、隐身窗口行为和本地存储共享范围都是 P1 验证项。缓存隔离主要防止应用错误展示，不等同于对拥有本机或浏览器资料访问权的人加密保护。

年度读取路径：读取已登录/未登录磁盘缓存前，以及使用缓存结果或写入年度响应前，各发一次 `cache: no-store` 的同源主页 GET，比较响应的访问者与当前页面作用域；身份改变或无法确认就停止。完整页内画布恢复不重新逐年读取，只在显示前核对一次身份，且不超过任一源年缓存期限；核对前保持画布隐藏，失败清除。仍不提供离线免身份缓存展示。该检查不能保证识别请求间快速往返的账户或同一账户的 SSO/组织可见性变化，不为这些未验证情形增加 Cookie 读取或后台轮询。

## 当前年度缓存策略

存储使用 `chrome.storage.local`；只保留作用域、日期/数量、抓取时间及 schema/解析器版本，不保存原始 HTML。读取时校验记录、连续日期和非负整数数量；旧版本、损坏或过期视为未命中。按抓取时点确定有效期：当年快照 1 小时且跨日失效，之后跨年也不延长；跨年后重新获取的历史年快照为 30 天。这不是永久不变的承诺。

- 历史年份可复用，但不能宣称永久不变；当年需要刷新。
- 缺失、解析失败或身份不明不覆盖已有的有效记录。
- 不长期保存原始 HTML；仅保留所需日期/数量和最小来源元信息。
- 实现清除本地数据与手动刷新的可理解入口；具体 UI 在后续 MVP 中确定。
- 存储额度、写入失败、结构升级和损坏记录需要直接路径验证。不能用 `unlimitedStorage` 掩盖未测容量问题。

当前提供强制刷新和“清除此主页缓存”（仅当前访问者在当前主页的全部年度）。缓存读失败改为联网获取并提示；写失败保留有效网络结果并提示未缓存。失败响应不覆盖有效缓存。取消后不再启动写入；已经发出的 Chrome 存储操作不能撤销，其结果仍只属于原作用域。容量/淘汰及真实权限提示未验收，不提前增加通用淘汰层。
