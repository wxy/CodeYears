## 已确认的主要流程（逐年数据填入，待完整验收）

1. 用户正常访问 GitHub 个人主页。轻量脚本在贡献区原生 h2 内最左侧挂“城市 · CodeYears”，右侧接“贡献图”，其后保留 GitHub 原统计文字与原设置；默认选原图，完整显示日历与 Activity overview/蜘蛛图。不请求贡献历史、不读写贡献缓存，也不加载城市面板、建筑图片或渲染器。
2. 用户点击“城市 · CodeYears”或工具栏快捷打开，才加载城市面板及空场地/路网，再识别主页所有者与当前访问者并读取默认最近三年。自定义范围改好后点击“应用”；预留年份只用于展示范围与空间坐标，不创建虚假每日数据。
3. 城市模式仍整体隐藏日历、Activity overview/蜘蛛图及原统计/原设置，保留 Contribution activity 流水；顶部不另造城市合计。每个公历源年返回的已校验累计快照按所选年份真实日期筛选后，填入已取得的合并地块。尚未返回、未提供或未来的日期不补零，短过渡反映实际数据填入，不让用户另等一轮独立生长动画。
4. 素材按实际出现的地块增量载入，合并地块作为整体进入画面。新数据批次可以重新规划建筑，最终映射规则不变；单纯观看缩放和平移不重新规划。完整缓存也走相同填入过程，不为观赏而人为延长加载。正式 City 不再显示进度条、暂停、跳过或重播控件；取消、年份选择、缩放平移、全景和展开继续可用。
5. 失败或用户取消时，清除已经显示的部分数据地块，回到空场地/路网并提供重试，不能将部分结果留作完整成功。已校验年度缓存仍按原策略管理，不因清空画面伪造缓存失败。原图入口始终可用。
6. 切回原图、后台或导航时取消请求、清空可见数据并释放城市，恢复原生内容；再次进入仍重新核对身份。数据说明、每日明细、刷新/清缓存和右键保存帮助保留在“更多”。静止停止连续绘制，展开/收起保留当前画布与取景。

本轮在 `codex/city-profile-tabs` 沿用原 PR #39 实施逐年真实数据填入，替代此前“全部读完后统一裁切生长”的正式入口流程。City 左侧切换、原统计/设置仅原图显示及无大卡片边框继续成立。身份隔离、年度缓存、ISO 源年与日期筛选、最终地块映射不改；允许数据批次重新规划，不允许缩放重规划。Terrain、旧预览和公共时间轴不改。前轮报告保留，待追加本轮证据，不改写为新流程通过。[改造任务](tasks/CITY-PROFILE-TABS.md) 记录当前边界。

## 最新建筑设计阶段

用户已选择 [六款设计方向](design/city-buildings/v1/README.md)，分别生成透明素材并接入。原设计总览只作参考，不直接裁为图集。已针对用户反馈修复建筑与地图的主底边方向、缩放改变建筑与跨格融合的问题。素材标定是图像近似校正，建筑尺度是地块视觉尺度；不宣称物理比例准确或整体视觉已获接受。下一步先收敛整体观感，再完成二十年预算及剩余浏览器验收。

用户后续提出单元规范、变体、植被平地和季度道路，并授权替换到 City。已完成 [八张单元设计板](design/city-units/v2/README.md)，其中 22 款透明单元经首轮标定接入，另有 3 款旧中高层作为高贡献兜底；两种幼树复用新单树图片并缩小。统一地面投影、包络居中和每边至少 0.1 格试排退让共用同一绘制逻辑。警局、消防局、体育场、总站保留标定后的实际低矮比例，不拉高以冒充 H1 达标；完整建筑目录、隐藏角点、顶部与透明边缘仍待美术复核。具体规范见 [城市单元规范](design/CITY_UNIT_SPEC.md)。按 ISO 周归年，每13周分段，三条道路使用固定轴贯通所有年份；53周留在最后一段，混排短年仅末端一列并入路面。所选周年必要时读取相邻公历年，再以真实日期筛选；可用入口不足或当年未结束须提示，不把缺失/未来日期补零。五年景观带从所选最早年份起分组。当前按用户反馈继续改善放大细节与街区衔接，不把接入等同于最终视觉验收。

用户实测指出固定 5 倍放大仍看不清建筑，灰白底面使楼体孤立、街区缺少内部道路。当前已按实际投影比例放宽 City 的细节上限，并以绿地庭院、紧凑铺装、入户步道和沿合并地块边界的窄支路连接街区；这些实现已完成 [直接路径与真实 Chrome 检查](reports/CALIBRATED-CITY-INTEGRATION.md)，整体观感仍待用户验收，不因此改变数据映射或引入游戏系统。

## 视觉边界

2026-11-01 用户后续确认：补齐2×1/1×2 H3/H4双变体并恢复同档合并；零值自然地块只用于整体空旷环境，广场依赖周边建筑密度，其余城市零值用铺装；五年分隔带统一为连续河道/岸线/步道和桥，季度路口加入静态信号灯。这些已补验并按本轮授权随#22/#23/#24合入，主线`c25436b`；地面与灯具不改变每日贡献或引入交通游戏系统。可叠加楼层仍是后续设想，未实现。

奇观采用独立 [v4单元](design/city-units/v4/README.md)：剧院3×3、体育馆/地标公园4×3，先在完整日期格内筛选并预留，再处理其余普通合并。初版每年最多两处，不跨年度/季度路或缺失日期。稀疏区域不凑数；以区域密度和覆盖表达强度，不把奇观主体高度误作每日贡献或物理楼层。普通合并规则仍按原有同档矩形执行。环路与多桥属于本轮追加交付，实际验证状态见对应报告。

- City 当前使用住宅、商住楼、公寓、办公楼、塔楼、警局、消防局、体育场与总站。阈值为每日 0=平地、1–2=幼树、3–5=树木、6+=建筑；建筑按相对强度分档，同年同档按实际支持的矩形占地合并，普通单元首批最大占地为 3×3，新增奇观可为 4×3，均不跨季度道路。具体阈值不是已冻结产品决策，也不要求合并成员数量逐个相等。每个 ISO 周年有52或53个完整周；年界可跨公历1月1日，真实日期不变，当年不补未来零值。缩放不改变建筑、合并与原始数据。地块草地、水体、广场和植被表示贡献等级；五年景观带树木、水体、道路仅作装饰。车辆仅为静态装饰，不引入行人或交通游戏系统。
- 画布透明并跟随 GitHub 背景，地景边缘渐隐，Terrain 不另铺矩形底板。Terrain 用真实数量的对数强度，经局部平滑、相对起伏、褶皱调制和边缘收敛塑形成连续山脊；绿色低地、灰绿高地、岩石与雪顶随当前高度显现；高度不是实地海拔，也不等于某日精确数量。远景空间分组只改变表现，原始总量和每日明细始终保留，具体映射与阈值尚未冻结。
- Signature 与 Natural 是已确认的主题名称；具体配色、材质参数与数值映射尚未冻结。
- 轻量、清晰反馈和自然动画优先于复杂特效；减少动态效果的系统偏好需要纳入验收。
- 不删除 GitHub 原生贡献日历与 Activity overview DOM。城市模式临时隐藏这组原生内容及原统计/原设置，切回或导航还原；root 外的 Contribution activity 流水不受切换影响。失败时仍能返回原图，页面内展开不是独立产品网站。

## 技术待验证项

- 同源贡献页面能否在现有会话下可靠按年获取；响应形式、登录重定向、限流与站点导航行为。
- 每日数量解析、日期范围、零贡献、闰年、语言和年份差异；页面显示总数与逐日合计是否一致。
- 当前访问者的可靠识别、登录切换与缓存失效；权限或私有贡献可见性变化。
- 内容脚本、资源加载和所需权限的最小组合；Chrome / Edge 的实际行为。
- 20 年数据下 City 与 Terrain 的性能、静止帧停止、后台暂停与资源释放。

上述均不能因产品选型已确认而标记为已验证。

## 后续设想

只有扩展取得真实使用与传播反馈后，才考虑另立免费独立网站项目，承载确实受扩展形态限制的体验。目标是传播、引流与声誉，不是收费。现在不建设网站，也不为它提前加入登录、服务器或通用平台框架。

动画导出、可分享作品链接、独立窗口视图、自动画质分级和社区协作可记录为候选，尚非首版交付承诺；本轮确认的页面内展开另按上文实施。仓库已于 2026-10-29 按用户决定公开，许可证以根目录 LICENSE 与素材说明为准，尚未商店发布。

## 维护规则

新增决策注明来源与日期；验证结论记录环境、输入和实际结果；设想只有经确认后才能进入首版范围。功能未实现、已实现未验收、已验证与已发布分别记录。

## 当前图片保存范围（2026-11-01最新决定）

用户已实际发现Chrome可在城市画布右键“图片存储为…”或“复制图片”，决定直接采用这一路径。提示用户先调整缩放、平移与生长状态，再右键保存当前画布。它保留当前取景和画布实际像素，不保存画布外的整座城市、不包含网页控制与GitHub页面背景；透明部分保留透明。正式City为Canvas 2D，不阻止默认contextmenu，不增加插件导出画布、Blob编码或分享权限。

前轮8K PNG/分享预览已从当前实现撤回；此前2048当前取景、2400总览、4K收藏、按年切图等候选不再作为当前开发计划。历史实验记录保留在报告中。Edge的原生菜单需随其真实浏览器验收核对，不能用Chrome结果代替。
