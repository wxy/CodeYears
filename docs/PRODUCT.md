# 产品定义

状态：奇观、双向车道、四类静态车辆已随#25–#30合入；本轮统一贯通季度道路、两侧绿化带年份雕塑、图片外围地貌与出城公路，并收敛City首发界面。完整发布与性能预算仍待验收。更新日期：2026-11-01。

本文件记录产品范围。技术可行性见 [数据与隐私](DATA_AND_PRIVACY.md)、[性能](PERFORMANCE.md)，开发状态见 [路线图](ROADMAP.md)。

“真实数量”指当前访问者在 GitHub 贡献页面被允许看到的每日贡献数量，不代表全部 Git 提交，不保证能看到隐藏的私有活动。不以颜色等级生成估计数量。

## 计划中的主要流程

1. 用户正常访问 GitHub 个人主页。只进行必要的页面识别，提供轻量入口；不自动请求全部历史或初始化 Three.js。
2. 用户选择年份范围，生成City。识别主页所有者与当前访问者，读取对应年度缓存，按需补齐缺失数据。
3. 数据通过校验后交给时间轴；先显示完整平地，整个城市共同生长。数据获取进度与景观生长进度是两个独立状态，生长百分比不是某日贡献已呈现的计数。
4. 用户可暂停、继续、跳过到已可用的最终状态。完整缓存不会强制跳过动画。加载中、失败和部分年份缺失要有明确状态。
5. 画面静止停止连续绘制；隐藏标签暂停；关闭、离开主页或销毁视图后释放资源。原生 GitHub 内容继续可用。

当前已实现主动打开、起止年份、逐年加载、年度统计、完整缓存重播、暂停/继续/跳过、固定视角缩放/平移/重置及关闭。City 按工作周排列并固定合并结果，季度道路以额外空间插入，不删除日期。透明素材按地面包络居中留距，造型与颜色按地块稳定选择。首发入口仅City；既有Terrain共享数据/时间轴能力保留但暂缓。失败或取消不展示不完整历史。透明画布和 UI 跟随 GitHub 明暗，Signature / Natural 主题选择尚未接入。后台沿用身份保护策略，清空结果并销毁风景，返回后重新生成。[预绘城市报告](reports/PREPAINTED-CITY.md) 只记录前一版六款素材的验证，不自动覆盖本轮集成。

## 最新建筑设计阶段

用户已选择 [六款设计方向](design/city-buildings/v1/README.md)，分别生成透明素材并接入。原设计总览只作参考，不直接裁为图集。已针对用户反馈修复建筑与地图的主底边方向、缩放改变建筑与跨格融合的问题。素材标定是图像近似校正，建筑尺度是地块视觉尺度；不宣称物理比例准确或整体视觉已获接受。下一步先收敛整体观感，再完成二十年预算及剩余浏览器验收。

用户后续提出单元规范、变体、植被平地和季度道路，并授权替换到 City。已完成 [八张单元设计板](design/city-units/v2/README.md)，其中 22 款透明单元经首轮标定接入，另有 3 款旧中高层作为高贡献兜底；两种幼树复用新单树图片并缩小。统一地面投影、包络居中和每边至少 0.1 格试排退让共用同一绘制逻辑。警局、消防局、体育场、总站保留标定后的实际低矮比例，不拉高以冒充 H1 达标；完整建筑目录、隐藏角点、顶部与透明边缘仍待美术复核。具体规范见 [城市单元规范](design/CITY_UNIT_SPEC.md)。季度按最近整周边界归属，再将每季放入14列展示区，三条道路使用固定轴贯通所有年份；空余空间并入相邻路面，作为无日期的铺装路肩，缺失/未来日期不补零。五年景观带从所选最早年份起分组。当前按用户反馈继续改善放大细节与街区衔接，不把接入等同于最终视觉验收。

用户实测指出固定 5 倍放大仍看不清建筑，灰白底面使楼体孤立、街区缺少内部道路。当前已按实际投影比例放宽 City 的细节上限，并以绿地庭院、紧凑铺装、入户步道和沿合并地块边界的窄支路连接街区；这些实现已完成 [直接路径与真实 Chrome 检查](reports/CALIBRATED-CITY-INTEGRATION.md)，整体观感仍待用户验收，不因此改变数据映射或引入游戏系统。

## 视觉边界

2026-11-01 用户后续确认：补齐2×1/1×2 H3/H4双变体并恢复同档合并；零值自然地块只用于整体空旷环境，广场依赖周边建筑密度，其余城市零值用铺装；五年分隔带统一为连续河道/岸线/步道和桥，季度路口加入静态信号灯。这些已补验并按本轮授权随#22/#23/#24合入，主线`c25436b`；地面与灯具不改变每日贡献或引入交通游戏系统。可叠加楼层仍是后续设想，未实现。

奇观采用独立 [v4单元](design/city-units/v4/README.md)：剧院3×3、体育馆/地标公园4×3，先在完整日期格内筛选并预留，再处理其余普通合并。初版每年最多两处，不跨年度/季度路或缺失日期。稀疏区域不凑数；以区域密度和覆盖表达强度，不把奇观主体高度误作每日贡献或物理楼层。普通合并规则仍按原有同档矩形执行。环路与多桥属于本轮追加交付，实际验证状态见对应报告。

- City 当前使用住宅、商住楼、公寓、办公楼、塔楼、警局、消防局、体育场与总站。阈值为每日 0=平地、1–2=幼树、3–5=树木、6+=建筑；建筑按相对强度分档，同年同档按实际支持的矩形占地合并，普通单元首批最大占地为 3×3，新增奇观可为 4×3，均不跨季度道路。具体阈值不是已冻结产品决策，也不要求合并成员数量逐个相等。每个年份通常需要 53 个边界周列，必要时 54 列，保留真实日期；当年不补未来零值。缩放不改变建筑、合并与原始数据。地块草地、水体、广场和植被表示贡献等级；五年景观带树木、水体、道路仅作装饰。车辆仅为静态装饰，不引入行人或交通游戏系统。
- 画布透明并跟随 GitHub 背景，地景边缘渐隐，Terrain 不另铺矩形底板。Terrain 用真实数量的对数强度，经局部平滑、相对起伏、褶皱调制和边缘收敛塑形成连续山脊；绿色低地、灰绿高地、岩石与雪顶随当前高度显现；高度不是实地海拔，也不等于某日精确数量。远景空间分组只改变表现，原始总量和每日明细始终保留，具体映射与阈值尚未冻结。
- Signature 与 Natural 是已确认的主题名称；具体配色、材质参数与数值映射尚未冻结。
- 轻量、清晰反馈和自然动画优先于复杂特效；减少动态效果的系统偏好需要纳入验收。
- 不覆盖或删除 GitHub 原生贡献图；没有数据或 WebGL 不可用时仍保留正常浏览路径。

## 技术待验证项

- 同源贡献页面能否在现有会话下可靠按年获取；响应形式、登录重定向、限流与站点导航行为。
- 每日数量解析、日期范围、零贡献、闰年、语言和年份差异；页面显示总数与逐日合计是否一致。
- 当前访问者的可靠识别、登录切换与缓存失效；权限或私有贡献可见性变化。
- 内容脚本、资源加载和所需权限的最小组合；Chrome / Edge 的实际行为。
- 20 年数据下 City 与 Terrain 的性能、静止帧停止、后台暂停与资源释放。

上述均不能因产品选型已确认而标记为已验证。

## 后续设想

只有扩展取得真实使用与传播反馈后，才考虑另立免费独立网站项目，承载确实受扩展形态限制的体验。目标是传播、引流与声誉，不是收费。现在不建设网站，也不为它提前加入登录、服务器或通用平台框架。

截图导出、动画导出、可分享作品链接、扩展独立大视图、自动画质分级和社区协作可记录为候选，尚非首版交付承诺。仓库已于 2026-10-29 按用户决定公开；开源许可证和商店发布策略尚待决定。
