高倍近看实测发现整张地面缓存放大后模糊，当前增加视口尺寸的近景缓存：当 `scale > unit × 1.25` 时，按可见范围重画矢量底面、道路与原烘焙平地贴图；仅尺寸、缩放、平移改变时重建，镜头静止时的生长动画复用结果。远景仍使用上述 3072/48 缓存，关闭视图时两种缓存清零。该修复改善的是地面采样方式，不增加素材解码或重新执行单元标定；新增视口缓存的内存和交互开销仍待预算验证。

以上是当前实现与资源规格，不是完整性能验收。放大细节与街区衔接已有本轮直接功能检查；二十年首次解码/播放/平移的帧耗时、内存和功耗尚待记录；旧 3D 原型约 60 FPS 的证据不能迁移。较早各段继续保留为对应版本的历史记录。

## 已确认的性能边界

- 用户没有激活视图时，不加载 Three.js、不创建 WebGL、不预取全部历史。
- 静止停止连续帧；播放和交互只在有变化时绘制。
- 标签隐藏暂停；关闭视图或离开页面取消任务并释放 WebGL 资源。
- 不能明显妨碍 GitHub 的滚动、点击与导航；性能优先于高成本视觉效果。

停止绘制与释放显存是两个问题。保留场景可能仍持有 GPU 资源；必须验证 dispose 与上下文处理，而不是仅看 FPS。

## 20 年数据验证方法

1. 在系统临时目录生成确定性 20 年日历数据，例如 2006-01-01 至 2025-12-31，包含闰日，共 7,305 天。固定生成规则/种子写进报告，不将生成数据提交 Git。
2. 至少覆盖稀疏贡献、常规分布、持续高密度三种形态。数量到高度的映射需避免极值压扁整体，但不修改原始数量。
3. 用相同输入分别测试 City 与 Terrain，记录主题、窗口尺寸、DPR、浏览器版本、系统、CPU/GPU 和电源状态。
4. 验证未激活、首次激活、冷/完整缓存、历史生长、暂停/继续/跳过、缩放平移、静止、后台、恢复、关闭和导航。
5. 对照未安装/未激活扩展时的 GitHub 滚动与交互，观察页面长任务、CPU、内存及可取得的 GPU 证据。
6. 重复打开与关闭，记录 WebGL 上下文、几何/纹理/程序等可观察资源趋势。浏览器不提供精确显存时注明不可测，不用 JS 堆或 renderer 计数冒充显存。

模拟数据只能证明渲染负载，不能证明 GitHub 获取、统计口径或缓存隔离正确。真实数据与页面交互另按 [数据验证](DATA_AND_PRIVACY.md) 验收。

## 初步目标（尚未验证的工程目标）

| 目标 | 验证方式 |
| --- | --- |
| 20 年完整数据可展示 | 检查日期数量与场景范围，并记录资源与加载时间 |
| 普通桌面争取 60 FPS、较弱设备争取稳定 30 FPS | 测量播放和交互的帧耗时分布，记录具体硬件；不能泛称所有设备流畅 |

| 关闭/离开后资源回收 | 取消调度、释放对象与上下文，并观察重复周期是否累积 |
| GitHub 交互不受明显影响 | 同设备同页面对照滚动/导航/点击；依据基线设定验收阈值 |

已有原型包体积、初始化与 CPU 提交时间、帧间隔及资源计数样本；CPU/显存上限与长任务预算仍未确定。2026-10-30 主屏 25 Hz 时，Metal 六组与空白 RAF 均约 40 ms P50；同源码的独立窗口移到 60 Hz 内建屏幕后，六组 P50 均约 16.7 ms、P95 为 17.3–17.7 ms。原型在该设备/窗口条件下取得约 60 FPS 证据，不泛化为所有硬件/正式扩展通过。两轮窗口尺寸也不同，不计算所谓代码优化倍数；不因 25 Hz 的观察先搭建自动画质框架。
