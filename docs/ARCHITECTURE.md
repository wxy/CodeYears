# 技术架构

状态：已连接多年份历史、预绘 City / 连续 Terrain 与整体生长；本机 Chrome 主路径已检查，整体视觉、完整 MVP 和 P1-G 门槛待验收。更新日期：2026-10-31。

## 当前渲染实现

六款透明 PNG 已接入固定视角 City，Canvas 2D 绘制；Terrain 使用按需 Three.js 连续高度场。两者共享时间轴、缩放和平移状态，没有旋转输入。设计参考、正式素材与标定规范见 [素材说明](design/city-buildings/v1/README.md)，验证版本见 [本轮报告](reports/PREPAINTED-CITY.md)。数据、身份隔离、缓存和原始每日数量不因视觉方向变化而改动。

## 当前骨架

P1-A 提供主动点击注入的 Shadow DOM 年度数据诊断。P1-B 通过 `load-year.ts` 连接页面身份确认、缓存与年度请求；`year-cache.ts` 使用 `chrome.storage.local`，在读取边界校验作用域、版本、日期覆盖和有效期。已知身份在读缓存前、使用/写入结果前通过禁止浏览器缓存的同源主页请求再次确认；身份不明仅联网获取，不读写缓存。浏览器真实会话与跨标签页验收仍以报告为准。

扩展使用 `activeTab`、`scripting` 与 `storage`，不注册自动 content script。Shadow DOM 面板选择起止年份，通过 `loadContributionHistory` 升序复用年度加载器和历史组装；加载进度与网络/缓存来源独立显示，全部成功后才把完整可信日期/数量交给风景与时间轴。失败或取消停止后续年份，不把部分结果生成完整风景。生成时才动态导入 `landscape.js`；仅查看每日数据不会创建 WebGL。每日表格在展开时建立。缓存、强制刷新及清除继续使用原身份隔离路径；数据获取完成与动画完成分别维护。

`createLandscape` 负责共享时间轴、有限动画帧、尺寸/主题监听、缩放和平移及视图释放。City 在 `city-parcels.ts` 一次规划年度横向街区：周为列、周一至周日为行；年初/年尾不足周保留边界列，通常为 53 列，2012 年在本布局下为 54 列，不强裁成 52 列，也不把未来日期填零。每个合并地块保留明确的源日期索引与真实数量，不能用连续索引区间代表跨周成员。

每日 0、1–2、3–5、6+ 分为草地、灌木、树木、建筑。建筑数量经相对对数强度分四档，同年同档的相邻格贪心合并为矩形；当前最多跨 8 周列、4 个星期行，不越年度道路。具体阈值和上限是当前实现选择。`city-view.ts` 按合并占地、强度档和稳定位置选择六种预绘建筑；主色来自原图，不表示精确贡献数。规划、建筑类型与占地只在创建 City 时确定，缩放只改变投影尺寸、平移、可见范围和采样质量，不再重建合并。

City 地面、道路、组间公园和草木由本地 Canvas 代码绘制，六张 PNG 由 `city-assets.ts` 从扩展本地资源加载。景观带从所选历史起点每五年一组，组内普通道路，组间增加公园/湖泊；只在已显示组之间留带，三年不插带、二十年三条，不依赖贡献强弱。每张源图保留原样，运行时解码为 640×640 ImageBitmap；裁切、落地点和主底边角度按素材记录。地图采用 2:1 轴测投影；每张图片绘制时应用保持竖直边的仿射校正，使主地面方向靠近地图的 ±atan(1/2)。这不是把 AI 图片还原为物理相机或真实三维模型。按落地点远近排序绘制，视口之外跳过；整体生长用向上揭示，低建筑先完成，并非真实三维拉伸。

Terrain 独立 `terrain-view.ts` 继续跨年份连续，以对数强度、局部平滑、褶皱和渐隐边缘塑形；当前高度混合低地/高地/岩石/雪顶。其远景网格仍可降低细节，不把高度解释为精确数量。City / Terrain 切换保留播放头与缩放平移，不再请求 GitHub 数据；旧视图立即释放。进入 Terrain 才动态导入其 Three.js 分包并创建 WebGL，回到 City 即释放几何、材质、纹理和上下文。

两种画布均透明；UI 跟随 GitHub 明暗，主题/尺寸/交互变化请求单帧。暂停或完成后停止连续帧。关闭移除输入/主题/尺寸监听，释放 City ImageBitmap；素材尚在加载时关闭，晚到的图片也释放；部分图片失败则关闭已成功解码的图片并显示失败。没有远程素材、远程执行代码或新增依赖。

## 目标模块

| 模块 | 职责 | 约束 |
| --- | --- | --- |
| GitHub 适配器 | 识别主页、访问者、同源请求、响应提取 | 页面 DOM 和请求都是外部边界；规则须有实测依据 |
| 数据 | 校验日期/数量、排序、年度覆盖和统计对照 | 内部只接收校验后的真实每日数量；不依赖 Chrome API |
| 缓存 | 按访问者、主页所有者、年份读写；版本和刷新 | 当前直接使用 Chrome 存储，在读取入口校验；身份不明不复用缓存 |
| 时间轴 | 历史起点、播放头、暂停、继续、跳过 | 与获取进度解耦；完整缓存也从起点呈现 |
| 渲染 | City / Terrain、主题、相机、按需帧、释放 | 不直接发 GitHub 请求或访问 Chrome 存储 |
| 扩展 UI | Shadow DOM 入口、加载/失败反馈、控制 | 保留 GitHub 原内容，用户主动激活 3D |

边界以当前职责为准；确有需要时再提取实现接口。不为尚未启动的网站编写第二个平台适配器。

## 目标数据流

```text
个人主页 + 当前访问者
  → GitHub 适配器（识别身份和年度页面）
  → 当前身份的年度缓存命中 / 同源请求补齐
  → 入口解析与校验 → 可信年度数据 → 对应作用域缓存
  → 完整或明确标记缺失的历史数据
  → 时间轴播放头（独立于请求/缓存进度）
  → City / Terrain 渲染
```

未取得数据的日期不是零贡献。缓存完整不等于动画已播放；跳过动画也不等于网络已经补齐。部分成功需要显式表达可用范围，不能悄悄构造完整历史。

## 平台与构建

- TypeScript 定义数据、缓存作用域与播放状态；Vite 生成本地 MV3 资源。
- 风景入口、Terrain / Three.js 分包及建筑 PNG 随扩展安装包打包；注入脚本仅类型引用，用户生成风景时通过 `chrome.runtime.getURL()` 动态 `import()` 本地模块，不执行 CDN 远程代码。
- UI 使用 Shadow DOM 隔离样式；它不是身份或数据的安全边界。
- 首版计划在 GitHub 页面上下文可用的位置完成同源数据请求；不能假设后台服务可以自动复用完全相同的会话语义。
- popup 通过 `scripting.executeScript` 注入本地 IIFE，不需要常驻 service worker 或自动 content script。popup、注入 IIFE、风景 ES 模块三次构建到同一目录；manifest 将 `landscape.js`、`chunks/*.js` 和 `assets/city/*.png` 仅向 `https://github.com/*` 声明为 web accessible resource，供隔离环境动态加载。
- content script、扩展页面与页面脚本的执行环境不同；若实测确需桥接，再针对真实数据边界设计消息协议，不预先增加 MAIN world 注入。

Chrome 官方说明了内容脚本的隔离执行环境和可用能力，不能由此推导 GitHub 会话请求已经通过：[Content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。

## 生命周期目标

| 状态 | 目标行为 |
| --- | --- |
| 未激活 | 轻量入口；无 Three.js、WebGL、历史批量获取或连续帧 |
| 激活/加载 | 识别身份、可取消请求、加载本地渲染模块 |
| 播放/交互 | 仅在有视觉变化时申请帧；日期数量不逐帧重建 |
| 暂停/静止 | 无连续帧；必要的单帧更新由 invalidate 触发 |
| 标签隐藏 | 当前扩展为身份保护而清空结果、取消请求并释放城市，返回后重新确认身份再生成；独立本地预览仅暂停 |
| 关闭/导航离开 | 取消请求和待执行帧，移除监听，释放几何/材质/纹理/renderer/context |

GitHub 的页内导航、浏览器后退、主页切换和重复激活必须实测。不能只处理整页刷新，也不默认使用全页面高频 DOM 轮询。

## 错误与边界校验

外部页面响应、持久化缓存及跨环境消息各自在入口集中校验，内部使用可信类型。失败明确区分网络、会话、身份不明、解析不支持、缓存不可用与 WebGL 不可用；不给未知数据填零。

只在可以恢复或转换错误的层处理异常。页面结构失配时停止该路径并保留原 GitHub 页面。缓存结构版本与解析器版本的失效策略在 P1 确定。
