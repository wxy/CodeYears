# 路牌脚点、视觉字号、车辆通行与 storage 生命周期

2026-11-11。继续更新 PR #79，基于 #78 的 `9751587`；实现、本机 dist 与下述直接路径完成，未合入或发布。前轮交互和返程规则见 [返程与编辑](ROAD-RETURN-AND-EDITING.md)。

## 本轮修正

1. 用户报告 `content.js` 读取 `onChanged` 时抛 TypeError。当前道路模块在创建时保留可用的 storage 事件对象，销毁时取消该对象的监听；没有 storage API 时跳过监听注册。原读取失败状态和保存门槛保留，不把失败伪装成成功或写入空配置。
2. 原路牌只从路肩退开固定 2 单位，没有包含牌宽及脚点；小镇北侧出口还会与额外分岔相交。现在依据完整素材横向包络和 0.8 单位余量退到路缘外，统一放在分岔另一侧，临时返程沿同侧前移错开普通牌。不改公路、建筑或贡献日期布局。
3. 原运行图基于 512 上限离线转换，实际只有 151–282 px 宽；大倍率显著放大了已丢失细节。现从保留的 1774×887 原图按 2048 上限重新标定、裁切，文字仍实时矢量绘制。原图内容和控制点不改，不把旧小图直接插值放大。
4. 用户确认要“牌面文字与路面文字看起来接近大小”。整体牌面改为原标定尺寸的 55%，保留此前短杆比例，按两种投影中垂直于文字基线的字高计算字号；四个主方向等于路面字号的一半。常见 ID 一行，宽高不足才分行缩排。低饱和灰蓝/灰绿继续区分出城/返程，去掉鲜亮交通蓝；配色校正在离线烘焙中完成，没有帧内滤色。
5. 车辆素材的 xp/zp 车头命名与显示一致，错误来自布车的侧向偏移与停止线、路面文字相反。两种城市规划的车辆统一偏向行驶方向右侧；桥面只改变布车取样偏移，不修改桥中心线、车头角度或 PNG 镜像。

## 环境与输入

macOS，Chrome 157，Node v26.7.0，Playwright 1.62.1。MV3 使用独立临时 Chrome 配置、真实 dist、1440×1100、设备 DPR 2（渲染器既有上限 1.5）。GitHub 贡献仍由真实公开页面取得；本人操作仅在公开 HTML 注入受控 `user-login=wxy`，不冒充真实登录或私有权限验收。

- wxy 八槽：octocat、torvalds、antirez、jashkenas、sindresorhus、yyx990803、tj、abcdefghijklmnopqrstuvwxyzabcdefghijklm。最后 39 字符只用于排版，不访问或声称账号存在。octocat 设置 `[torvalds,null,null,null]`，用于出城和独立返程同时存在的检查；不是对账号真实关系的断言。
- 车辆使用仓库现有 `probes/city-organic` 完整浏览器对照页：20 年持续密集、2006–2025 ISO 窗口，逐日 `6+i*17%65`，同时绘制原矩形城市和有机地图。近景另选一年持续密集。

## 实际结果

| 路径 | 结果 |
| --- | --- |
| 两种地图八路脚点 | 通过；记录实际 Canvas 图片变换，按每张源画布 alpha 的左右脚底取样，128 个脚点均不在任何出城路面多边形内 |
| 独立返程脚点 | 两种地图均通过；同时检查四个普通出口及绿色返程，不占道路半幅 |
| 牌面/路面字高 | 两种地图各四个默认出口，实际 `measureText` 包络及矩阵算出的垂直字高比均为 1 |
| 高倍率与配色 | 实际展开地图，围绕牌面放大到该视图上限；现代约 847%、小镇约 1547%，查看原画细节、文字和脚点；低饱和出城牌、绿色返程均检查 |
| 当前有机城市车辆 | 完整浏览器页 40 辆均在朝向右侧，四种车型均包含，输入守恒检查通过 |
| 原矩形地图车辆/桥 | 180 辆中 178 辆可唯一归属的采样通过，其中 18 辆在桥面；另 2 辆处于旧环路与年度路面重叠区，无法唯一归属，不把它们写成单一路段验证通过 |
| storage 不可用时销毁 | 在实际扩展 isolated world 移除 `chrome.storage` 后触发 Turbo 销毁，未出现 onChanged 异常 |
| storage 不可用时首次打开 | 受控移除 API 后打开完整城市，读取失败有明确状态、提交禁用，没有虚假保存；无未处理异常 |
| 刷新恢复 | 页面刷新后八条已保存道路恢复，原数组不变，正常注册新监听 |
| 构建和最终异常 | TypeScript、最终 dist 通过；最终直接路径页面未处理异常 0、扩展缺失资源 0 |

真实 `chrome.runtime.reload()` 探针里 runtime ID 失效，但本机 Chrome 仍保留已访问的 storage 对象，未自然重现用户的异常；因此不把“扩展重载是用户现场根因”写成结论。移除 API 的受控路径覆盖的是报错所需条件及实际挂载/销毁调用链，现场触发环境仍待用户重载验证。

脚点第一次检查发现小镇北路会压到邻近分岔，随后将牌放到分岔外侧再测通过。车辆判断以车头向量与道路侧向的叉积为准，不能仅从最近中心线推断原矩形路网里的重叠路面；不为这个既有探针问题扩展修改路网。

## 复现方式

```sh
node scripts/bake-direction-boards.mjs
npm run build
CODEYEARS_ORGANIC_CACHE="$TASK_TMP/vite-cache" npm exec vite -- --config probes/city-organic/vite.config.ts --port 4189
shasum -a 256 dist/content.js dist/landscape.js
```

`TASK_TMP` 为本轮独立系统临时目录。MV3 沿用 Playwright 本机 Chrome，去掉默认 `--disable-extensions`，启用 `--enable-unsafe-extension-debugging`，通过 browser CDP `Extensions.loadUnpacked({path: distPath})` 装入。options 页写入上述明确输入。

1. 到 wxy 城市，等真实读取和短填入完成，Fit view；两种地图分别记录主 Canvas `drawImage`/`fillText`。图片两段绘制中仅取下方支架那次的实际变换。源图 alpha 左/右下沿取脚底代表点，换算成 CSS 位置，与同倍率八块道路多边形比较。
2. 使用 `measureText` 真实字形高度乘变换矩阵行列式、除以文字基线长度，比较 octocat/torvalds/antirez/jashkenas 的牌面和路面字高。展开地图，围绕牌面缩放到上限查看。
3. 点击 octocat，切换两种地图检查绿色返程，点击牌面回 wxy，比较八槽不变。
4. isolated world 中移除 `chrome.storage` 后触发 `turbo:before-render` 检查销毁；在新页面移除 API 后首次打开城市，检查读取失败和禁用保存；刷新恢复。没有伪造成功写入。
5. 浏览器打开 4189 既有探针，选 20 年持续密集并等两个地图均完成。对车辆朝向求右侧法线，检查相对对应中心线的带符号距离大于零；桥面使用缓和曲线最近点。原矩形输入与画面相同，通过 Vite 的只读浏览器模块取得同份规划；无法唯一归属的重叠路面单独记录。切一年近景查看四种精绘车辆。
