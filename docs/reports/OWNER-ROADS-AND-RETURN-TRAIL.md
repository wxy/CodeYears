# 本人道路、实体路牌与多跳返程

日期：2026-11-11。状态：实现完成，编译通过；真实匿名多跳访问和受控身份权限路径分开验证。继续更新 PR #79，尚未合入或发布。之前的浮动路牌报告保留历史范围。

同日后续：路牌的尺寸、牌面名称、透视和整段路面操作已由[大型方向牌报告](CITY-DIRECTION-BOARDS.md)更新。下文画面、点击范围和构建哈希只对应本阶段；本人权限、配置和多跳返程记录保留原验证范围。

## 最终行为

- 添加、修改、移除只对“当前登录访问者与 Profile 相同”的本人城市开放。匿名、其他账号或未知身份不提供添加入口；写入前再次使用已有 `confirmViewer` 联网核对，页面或身份变化则保留原设置。
- 路牌位于每条出城道路尽头的路肩，脚点与 Canvas 共用世界投影；现代城市是金属牌，小镇是木牌，底座采用 2:1 投影，箭头随道路出城方向翻转。点击后打开卡片：空牌为“添加道路”，已有目的地显示“@账号 的城市”及前往链接。只有城主看到修改/移除操作。
- 原有四至八槽配置不迁移、不删除，只有本人可增加下一条待设置道路；其他城市已有的本机配置可只读访问，不代表本轮取得了对方公开发布的路线。没有新增公开共享通道、Token、后端或自动关系发现。
- 返程牌独立放在入城一侧，不替换对方原有出城牌，也不占八条出城道路的名额。A→B→C 后，C 的返程卡片列出 B、A；回 B 后仍可回 A，直接回 A 则截短后续路径。浏览器回退保留各历史项原来的路径。
- 旅行路径只属于当前访问者、当前标签，绑定浏览器的稳定历史项 key，保存在 GitHub 同源 `sessionStorage`。刷新和地图类型切换可恢复；切换访问者后不显示其他账号的路径。URL 片段仍只有地图类型，不传整条路径。
- 已有 S / 斜杠输入隔离、Enter 保存、Escape 取消、身份与贡献缓存隔离保留。实体路牌随缩放/平移定位；全景可查看所有出口。

## 验证环境与输入

macOS，Google Chrome 157.0.8103.39，Node v26.7.0，Playwright 1.62.1；1280×1000 视口，独立系统临时浏览器资料，通过 browser 级 CDP `Extensions.loadUnpacked` 加载实际 MV3 构建。未打开个人 Chrome 配置、复制 Cookie 或使用真实账号凭证。

两类证据严格分开：

1. **真实匿名页面**：实际访问 `wxy`、`torvalds`、`octocat`，请求和贡献解析均走真实 GitHub。通过真实扩展存储预置本机路线 `wxy→torvalds`、`torvalds→octocat/antirez`、`octocat→jashkenas`，用于验证只读访问和多跳。预置是测试输入，不是对公开账号真实道路关系的断言。三座城市的道路数组在访问前后逐项相等。
2. **受控登录身份**：仍加载实际 MV3 扩展和公开贡献，但仅拦截完整 Profile HTML 的 `meta[name=user-login]`，将访问者设为 wxy，或在保存前改为 torvalds；不修改年度贡献响应，不模拟存储或渲染器，也不发送实际登录/修改账号的请求。这验证客户端身份合同及写入前核对，**不等于真实登录、SSO 或私有权限验收**。

受控八路输入为 `torvalds`、`octocat`、`antirez`、`jashkenas`、`sindresorhus`、`yyx990803`、`tj`、`gaearon`。本人四路填满后通过真实表单和 Enter 添加下一条；八路已满时另加一块返程牌，核对八块出城牌仍在原槽位。

## 实际发现及修正依据

- 初版把返程路径附加到 `history.state`。真实 GitHub 刷新失败时，记录显示该对象已经只剩 GitHub/Turbo 字段；刷新前后原生 `navigation.currentEntry.key` 相同。说明依赖站点会重写的状态导致了丢失。改用当前标签 `sessionStorage`，以原生历史项 key 索引，并保持站点状态不变，之后刷新和回退路径通过。Chrome 的[Navigation API 文档](https://developer.chrome.com/docs/web-platform/navigation-api)说明该 key 在同一历史项的 URL / state 更新时保持稳定；本轮另以实际浏览器验证刷新前后值相同。
- 八路检查发现，后加入的透明路面链接遮住了先加入的路牌。将实体牌放在路面命中区之上后，两种地图的八个牌均可实际点击。没有强制点击或忽略命中失败。
- 最后视觉检查发现透明路面链接残留蓝色文字，已清空该纯命中区域的文本，保留标题与链接事件。此后只补编译与对应视觉检查，导航和权限代码不变。

## 复现方法

```sh
TASK_TMP=$(mktemp -d -t codeyears-owner-wayposts)
npm run build -- --outDir "$TASK_TMP/build"
# 按下列顺序验证实际构建；完成后按用户要求生成重载目录。
npm run build
```

临时 Chrome 加载方式沿用[前轮报告](ROAD-SIGN-EDITOR.md)：Playwright 指向本机 Chrome，`ignoreDefaultArgs: ['--disable-extensions']`，仅临时配置使用 `--enable-unsafe-extension-debugging`，在 browser session 调用 `Extensions.loadUnpacked`。通过该临时扩展的 `options.html` 写入上述路线输入与语言偏好，真实 `chrome.storage.local` 不作替换。

1. 匿名依次从 wxy 路牌卡片进入 torvalds、octocat；检查 C 的返程列表、刷新、切小镇、回 B、再次去 C 并直接回 A，再执行浏览器后退。比较三组原道路设置完全相等。
2. 在受控身份下打开 wxy，点击空牌输入并保存；修改前保持 DOM 为 wxy，但把下一次完整 Profile 身份响应改为 torvalds，确认原设置未变。恢复身份，再去他人页面确认没有编辑操作，返程后确认本人编辑可用。
3. 预置八槽输入，两种地图逐个点击八块牌；从 torvalds 的既有只读路牌进入 wxy，确认同时有八个出城牌和一块返程牌。切换受控访问者并刷新，确认路径隔离，再恢复原访问者。
4. 把本人设置改为三个已指定加一个空槽，通过第四块牌添加，确认出现第五块可添加实体牌。最后检查两种实体牌画面和透明路面区域无常驻文字。

最终本机 `dist/` SHA-256：`content.js` 为 `553f915df3f1c855c2ca88380cc4ba593e47e618eb922008004659f308059e2d`，`landscape.js` 为 `32f110b01f9141c8b2602c544cb6f38602fafb362dc5e977e202c5f01b6e6b18`。主多跳/权限路径与后续牌形、层级、纯文本修正按上述影响分别验证，不冒充每一项都对同一哈希全量重跑。
