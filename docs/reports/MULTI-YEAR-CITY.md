## 受控完整 UI 的失败、取消与恢复

系统临时页面加载实际注入脚本与 City 模块，只适配当前页面 URL 为 GitHub 主页。虚构主页 octocat、访问者 alice；边界 fetch 返回内存生成的年度 HTML/身份 HTML，Chrome 存储由 Map 替代，其余年度加载、解析、缓存、组装、时间轴和 UI 均为真实模块。不是实际 MV3 或真实身份切换验收。

输入按 UTC 日历生成 2023–2025 全年日期；0 起始 index，闰日或 `index % 7 === 0` 为零，其余 `index % 5 + 1`。生成 `data-date`、英文 `tool-tip[for]` 与年度标题合计。2023 为 365 天/936，2024 为 366 天/932，2025 为 365 天/936；合计 1096 天/2804。

| 路径 | 实际结果 |
| --- | --- |
| 第二年 HTTP 503 | 仅年度请求 2023、2024；显示已读 1/3 年及 HTTP 503，不请求 2025；缓存 1 项，Canvas 为 0 |
| 强制刷新中第二年延迟并取消 | 先显示已读 1/3 年；取消后操作按钮恢复，不请求 2025；缓存仍 1 项，Canvas 为 0 |
| 失败/取消后正常重试 | 2023 命中缓存，2024/2025 联网；来源 2 网络/1 缓存，1096 天合计 2804；Canvas 为 1，观察到 9/1096 的生长 |
| 起始晚于结束 | 显示明确错误；年度与身份请求计数不变 |
| 单年数据入口 | 2024 命中缓存、366 天合计 932；仅查看数据时 Canvas 为 0，展开前 0 行、展开后 366 行并包含闰日 |
| 关闭面板 | 面板和 Canvas 为 0，原生样式的占位贡献日历仍为 1 |

复现时在临时本地页面提供上述年份链接、日历与身份 meta，打包 `content.ts` 时只替换 `new URL(location.href)` 边界。替身 fetch 的年度分支依据 `from` 选择生成 HTML，身份分支返回 alice 的完整 HTML；第二年分别返回 503 或延迟 5 秒并响应 AbortSignal。存储替身实现 get/set/remove 并在页面显示年度请求序列与项数。实际按上表完整 UI 路径操作；没有在实现后补写单元测试。
