# 全部路牌右置、返程右道与修改点击

2026-11-11。继续更新 PR #79，基于 #78 的 `9751587`；本机 dist 已更新，未合入或发布。取代前轮“把牌放到分岔另一侧、返程使用空白左半幅”的安装方案，保留高精度素材、配色、字号和车辆修复。

## 问题与修复

- 前轮为避开分岔统一使用负法线安装，独立返程的地面名称及命中区也取负法线半幅。它们实际在进城左侧，违背离城右侧通行的约定。当前普通出城、复用已有出口的返程和独立临时返程，一律使用离城正法线右侧；所有目的地文字都在右半幅，进城半幅留白。
- 右侧存在额外分岔时，单纯把安装方向翻转会重新压到邻路。当前出口均为直段；在安装位置横切可见出城路面，取最右车行面边缘，再加完整素材支架包络与原0.8单位余量。计算只在准备路牌时进行，没有新增帧循环、资源或地图数据。
- 独立返程与本城目的地共用第一条出城路时，右半幅沿道路分成两段：靠城段写来源 ID、点击返程；靠外段写原目的 ID、点击继续访问。文字可用宽度与点击多边形使用相同段范围。若该出口没有本城目的地，返程使用整条右半幅。已有指回来源的出口仍直接复用，没有额外牌或分段。
- 修改按钮的失败已在旧 dist 自然复现：其 `transform:translateY(-50%)` 被通用 `button:active {transform:scale(.97)}` 覆盖，按下后下移约15.24 CSS px，松手落在按钮外，未产生点击。改用独立 `translate:0 -50%` 定位，保留通用按压缩放，两种变换互不覆盖。没有替换成双击、长按或只允许右键编辑。

macOS，Chrome 157，Node v26.7.0，Playwright 1.62.1，1440×1100 headless，真实 MV3 dist、独立系统临时 Chrome 配置与真实公开 GitHub 读取。

- 右侧/跨城路径使用真实匿名访问者，旅程身份全程一致。wxy四槽输入 `[octocat,torvalds,null,null]`；八槽为 octocat、torvalds、antirez、jashkenas、sindresorhus、yyx990803、tj、defunkt。
- octocat四槽为 `[torvalds,null,null,null]`；八槽为 torvalds、antirez、jashkenas、sindresorhus、yyx990803、tj、defunkt、mojombo，另把第七槽替换为 wxy，检查额外出口复用返程。配置为明确的本机测试输入，不是账号真实关系。
- 修改按钮单独使用受控 `meta[name=user-login]=wxy`，贡献、原渲染器、扩展存储与保存前联网核对不替换；不作为真实登录/私有权限验收。

## 复现

```sh
npm run build
shasum -a 256 dist/content.js dist/landscape.js
```

Chrome MV3 沿用前轮 Playwright 本机 Chrome、移除默认 `--disable-extensions`、`--enable-unsafe-extension-debugging` 与 browser CDP `Extensions.loadUnpacked`。通过options页写入上述输入。

1. 旧版先对已聚焦的“修改”按钮上沿12%位置执行真实鼠标按下/松开，比较两次边框；确认跳位与卡片未打开。修复后两图八按钮分别在高度12%、50%、88%位置重复，核对预填ID，关闭后继续；再Tab/Enter打开并提交。
2. 对四路/八路两种地图，记录实际 `drawImage` 下方支架那次变换，从源画布alpha的左右脚底取代表点，换算为CSS坐标。相对离城道路向量计算正法线侧向距离，必须在右路缘外，并与所有出城路面多边形无交叠。
3. 记录主画布 `fillText`、`measureText` 四角及实际变换，四角必须在右半幅。独立返程时，来源文字应在 `.city-return-surface` 内、原目的文字在其外。
4. 用真实可见标字位置检查elementFromPoint与目标href，再执行wxy→octocat→wxy、octocat→torvalds→octocat，最后切换为已有第七出口返程。没有force click或触发DOM click绕过命中。
