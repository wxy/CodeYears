| 体育馆 | 4×3 | 0.808921 | 0.214133 / 0.100000 |

三者地面轴均校正为±0.5、包络中心等于原生地块中心，factor=1；公园kind=building，走建筑仿射而非平地四点映射。体育馆受占地限制低于1.1H目标；剧院弧顶、公园顶饰高于所选参考尺，不把参考值冒充整体物理高度。体育馆F为超出alpha框3px的圆角逻辑包络；部分隐藏后角与落地点为已声明近似。

奇观先选、再普通合并未占用日期。活跃≥90%、建筑≥80%、band≥2≥75%，每项向上取整；每年最多两处、不跨年度/季度路/缺日期，保留全部indices/count/mean。第一版按均值排名会使正式密集LCG三年六处全为小剧院；实际对照发现后改为建筑密度优先、日均贡献×√面积评分，兼顾贡献强度和覆盖范围。密集三年4×3由0变6，二十年由1变40；没有强制类型配额。完整纯规划23场景与复现见 [云端报告](CITY-WONDER-PLANNING.md)，不混为本地浏览器证据。

`planWeeklyCity`默认仍关闭；正式`planCityScene`与`createLandscape`默认启用完整目录，比较页可显式关闭。素材选择只做一次，生长/相机不参与规划；奇观数量预计算，不逐帧遍历地块。已无河中池塘绘制，移除旧兼容的强制pond-a预载键。

Node26.7.0、Chrome156/macOS，使用正式源码与既有锁定依赖。`npm run check`、`npx tsc --noEmit -p probes/city/tsconfig.json`、`npx tsc --noEmit -p probes/city-units/tsconfig.json`、`npm run build`与`git diff --check`通过。单元入口39/39加载，三款分别核对浅/深背景、原图/校正图及网格，实际指标与上表一致。

LCG沿用`src/renderers/probe/data.ts`原种子与生成算法。试排以每年1月1日前最近周一为零点，x周列/z周一行：x18–21且z4–6取60，x30–32且z4–6取50；其余x1–40取`3+index%5`，其他0，index为所选范围过滤后索引。它用于便捷观察两块高贡献区域，未冒充真实分布或最佳阈值。

布局指纹为对`items`的`[id,factor,x,z,w,d]`序列JSON做32位FNV-1a。二十年常规普通11778577、奇观1521048587；后者12次放大及原生拖动后不变。稀疏两侧2563287467、全零两侧2873801183。浅色试排全景/近景、深色二十年近景中奇观、道路和保留楼群已观察。二十年重播暂停于3%，后续仍3%；继续/跳过成功，关闭两画布归0，再生成恢复2。没有把UI百分比稳定称作精确帧耗时或FPS证据。
