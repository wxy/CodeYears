# City 二十年本机性能基线

日期：2026-10-31。源码基线：PR #15 合入提交 `e432b1020518df414819b7202f305e53fbda218d`；本分支 `codex/city-local-performance` 仅新增任务和报告，不改渲染器。

**结论：取得当前 M1 / Chrome / 60 Hz 内建屏幕的 Canvas City 基线，但完整性能预算未通过验收。** 全景生长多数帧接近屏幕的 16.7 ms 节奏，CPU 提交 P50/P95 为 5.8/10.0 ms；首次全景阶段存在一次 327.3 ms 绘制提交峰值及 149/335 ms 长任务，不能称为全程无卡顿。5 倍与约 22 倍近景较轻，离散拖动、暂停停帧和可观察资源清零通过。没有以此替代显存、浏览器内存、功耗或真实 GitHub 集成验收。

## 输入、命令与观测方式

复用本提交的 `src/renderers/probe/data.ts`、`generateDays('regular')`：UTC 2006-01-01 至 2025-12-31，共 7305 天、93171 次示例贡献。种子 20060101，每日更新 `seed=(imul(seed,1664525)+1013904223)>>>0`，数量为 `seed%5===0?0:1+seed%30`。不读取真实账号、页面响应或缓存。

本轮临时目录前缀 `codeyears-city-perf-`，实际后缀 `zn63_h2a`。以 Vite 临时配置直接导入本分支的正式 `createLandscape` 与数据生成器，公用目录为本分支 `public/`，只监听本机回环地址 4181。命令与环境查询为：

```sh
node --version
sw_vers

CY_PERF_TMP=$(mktemp -d "${TMPDIR%/}/codeyears-city-perf.XXXXXX")

/Volumes/MacSSD/develop/CodeYears/node_modules/.bin/vite \
  --config "$CY_PERF_TMP/vite.config.mjs" --configLoader native
```

屏幕刷新率另外用临时 Swift/CoreGraphics 查询 `CGGetActiveDisplayList`、`CGDisplayBounds`、`CGDisplayCopyDisplayMode` 的 `refreshRate`，Swift 模块缓存指定在本任务临时目录。沙盒查询未显示完整显示器信息，取得只读授权后得到上述双屏数值；没有更改硬件设置。

临时页面在 Vite 的 `transform` 中，仅围绕正式 `layer.draw(progress,viewport)` 放置两次 `performance.now()`，记录 CPU 提交耗时，同时记录该次正式 RAF 的 `now`、视口与播放状态。素材准备从 `loadCityImages` 开始到成功返回烘焙结果计时；首次画面从调用 `createLandscape` 到首个 draw 返回计时。`PerformanceObserver('longtask')` 记录主线程长任务，包装 `createImageBitmap/close` 及 `document.createElement('canvas')` 记录可观察资源。每次读取通过页面按钮汇总到可见 `#metrics`，不从浏览器隐藏运行时读取；源码逐帧没有新增逐像素处理，计时与 DOM 汇总均只存在于本次临时页面。

每个生长阶段完整播放现有的 8 秒时间轴，使用浏览器真实 UI 依次启动：首次加载与全景 → 5 倍 → 细节上限。随后在近景完成态做五次真实离散拖动，再重播至暂停，间隔 5 秒核对计数，最后关闭。不替换 RAF/时钟，不人工派发指针事件；不额外运行构建或扩大稀疏/高密度矩阵。Vite 对临时变量路径的动态导入给出分析提示，实际模块和素材加载成功；提示未通过修改正式源码处理。

## 实际结果

首次画面耗时 **602.8 ms**，其中素材请求/解码/清理/烘焙成功返回的跨度为 **432.1 ms**，15 个文件、17 个运行 id、1,017,841 个烘焙画布像素。素材时间包含在首次画面时间中，不能将两者相加。此为本临时 origin 的首次加载，未清空浏览器全局缓存或系统文件缓存，不称作所有设备的冷启动指标。

| 阶段 | draw 样本 | CPU P50 / P95 / 最大 ms | RAF 间隔样本 | RAF P50 / P95 ms | 阶段长任务 |
| --- | ---: | --- | ---: | --- | --- |
| 首次全景生长，zoom=1 | 442 | 5.8 / 10.0 / **327.3** | 440 | 16.7 / 17.6 | **149、335 ms** |
| 5 倍生长 | 479 | 1.2 / 2.9 / 7.5 | 477 | 16.7 / 17.4 | 0 |
| 约 22 倍近景生长 | 481 | 0.7 / 1.0 / 6.6 | 479 | 16.7 / 17.5 | 0 |
| 近景完成态，五次离散拖动 | 8 | 0.9 / 4.3 / 4.3 | 不适用 | 不适用 | 0 |

近景阶段最后记录 `zoom=22.0924`；当前宿主的计算上限约 22.292，测量期间存在轻微视口调整，报告使用实际数值，不伪称严格固定上限。最后拖动视口为 `panX=100.538 / panY=1.149`。平移样本包含进入统计阶段的已排队单帧，不将这 8 个离散重绘样本当作连续拖动帧率或可靠的长时分位数。

前两次长任务都被当前阶段时间范围归入**首次加载/全景生长**，相对页面 time origin 的 startTime 为 31333.0、34547.1 ms。327.3 ms 的 draw 峰值也发生在该阶段。当前测量没有按素材/栅格调用细分，无法确定两次长任务各自的根因，不能直接归因为图片上传、解码或某种 GPU 行为。全景 442 次绘制也少于该屏幕 8 秒约 480 次的节奏，仅看 P95 会遗漏这类尖峰。

## 静止与资源

- 三阶段均完成 7305/7305 天。暂停专项在第 334 天，draw 总数 1434；5 秒后仍为 334 天、1434 次，没有续连续帧。
- 5 倍与近景往返未增加素材请求：15 次 fetch、30 个 ImageBitmap 创建和 30 次关闭。源位图在烘焙后即关闭，City 创建 WebGL 数为 0。
- 活跃时宿主一个画布；跟踪到的非零画布为 20，远景 7,435,393 像素，近景 8,875,393 像素。该计数包括烘焙及离屏缓存，并保留调试引用用于观察尺寸，**不能换算为实际内存或显存**。
- 关闭后宿主画布 0、跟踪画布非零数 0、总像素 0，ImageBitmap 仍为创建/关闭 30/30。没有测整个浏览器进程长期内存趋势、精确显存或功耗。

## 结论、下一步与清理

当前窗口条件下，5 倍与约 22 倍生长、离散平移、暂停停帧和可观察资源清零有证据。**完整性能预算仍未验收，首次全景尖峰需后续针对性定位。** 最小下一步是围绕首次全景阶段区分场景准备、首次大批楼体呈现与绘制提交，记录尖峰对应的位置后再决定是否优化；不因此先搭建自动降画质框架，也不为追求 PASS 重跑宽矩阵。

未完成范围：连续长时拖动、其他硬件/浏览器、所有密度、真实 GitHub 页面的交互影响、后台、内存/显存/功耗预算。后台和真实会话由独立本地浏览器任务报告，本报告不补写其通过结论。因为仅新增报告，没有重建未修改的正式扩展；校验本分支差异、引用、基线和正式源码未改即可。
