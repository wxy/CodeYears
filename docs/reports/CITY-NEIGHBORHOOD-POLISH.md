## 实现

年度主路用深灰绿，季度路稍浅且窄；连续暖石人行道、细路缘与克制草地连接年度街区。建筑底部铺装和短入口步道保留，只沿建筑地块边界画细步道，共享单位边去重；不再给每个草地/植被地块描深色闭合网格，也不切开合并建筑。季度路口两组过街带分别横跨各自道路，条纹随车行轴排列。五年公园保留曲径、池塘与装饰树。

全景和近景现在按同一绘制序列重放：淡出边缘 → 年度道路/人行道/季度路口 → 庭院与细步道 → 数据平地贴图 → 公园/曲径/池塘，再绘制原有生长中的楼体与树木。修正原实现把近景所有面/线分组后移造成的顺序差异。边缘使用世界坐标下低透明度层，两档一致；没有新增随机或常驻动画。远景缓存一次生成；近景仍只在尺寸、比例、平移改变时重建；销毁清零三个画布并清空绘制序列。

## 追加：二十年细节平移同步耗时对照

按主代理要求，针对全量重放可能影响近景平移的具体风险，在同一云端环境做一次直接对照。原基线为 `ac876352e899528669a6a760240d14818c2398b6` 的 createCityView，当前实现为 `30d3d833e6fcfe64e9593acee2b3935a59251ae6`。没有修改规划、素材选择或绘制实现；本次未观察到恶化，不增加包围盒过滤。

环境仍为 Linux 6.18.57、Node v24.19.0、Chromium 154.0.8037.57 headless，允许 SwiftShader。通过现有 preview:city 的 Vite 服务，在同一页面导入两份 createCityView，先派发 pagehide 停止原预览时间轴，再共享同一份 regular/2006–2025 数据（7305 天、93171 次）、同一 scene 和已加载/烘焙 images，分别建立视图。不含素材解码、场景规划与构造耗时。

浏览器窗口 1440×1000、DPR 1，直接传给 draw 的景观视口为 1156×620、DPR 1、浅色；zoom 为原基线 maxZoom 的 0.75，即 15.886120996441282，投影比例 144 CSS px/世界单位，明确进入近景缓存分支。progress 固定为 1。每次平移调用改变 panX/panY，必然重建近景地面缓存。预热四组后测十二组，组号 i=0…11，平移为 `(25i,12i)` CSS px；每组交替原基线/当前的先后顺序，每次 draw 前等待一个 requestAnimationFrame。用 performance.now 在 draw 返回时计同步耗时，不用截图或强制读回像素影响时序。
