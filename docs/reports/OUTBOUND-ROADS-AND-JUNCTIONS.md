# 出城链接、空白方向牌与环路接点

2026-11-11。状态：实现、类型检查、构建和下述直接路径完成；本机 `dist/` 已更新，继续更新 PR #79，未合入或发布。

## 本轮规则

| 场景 | 实际显示 |
| --- | --- |
| 出口未指定目标 | 纯空路牌，牌面无问号、文字或箭头，路面无名称 |
| 已知出城链接 | 牌面显示 GitHub ID；右侧出城半幅写目标 ID，进城半幅不写路名 |
| 从 A 抵达 B，B 没有指回 A 的已知出口 | 当前访问者看到临时 A 返程牌，沿用标签页路径，不写入 B 的配置 |
| B 已有指回 A 的出口 | 复用该出口，不再额外画返程牌；右键或 Shift+F10 仍可选更早城市 |
| 东西 / 南北道路 | 分别使用已有绿色/木色与蓝色款；颜色和造型只表示方向，不表示单双向状态 |

当前产品没有对方公开道路配置的发布/读取通道，因此移除此前通过其他账号本机配置推断双向的逻辑。道路模块只读当前 Profile 的配置；来源城市和地图类型来自本次访问路径。已知的返向出口足以用于返程，不需要全局双向状态。本人编辑、保存前实时身份核对、四至八槽、跨访问者隔离及直接点击访问保持原规则。

路牌原图复用不重画，运行 PNG 与清单按东西/南北重命名为 `direction-board-x` / `direction-board-z`。图像字节不变，原始提示词和源图中的 mutual 文件名作为历史制作记录保留；当前用途见[素材目录](../design/city-wayposts/v1/README.md)。

## 接点原因与修复

真实 wxy 城市在 400% 下的四个接点均显示：宽出城路由独立 painter 后画，其圆端帽及路缘压进原环路，遮住部分标线。接点中心已有正确的环路位置，问题出在分开铺路和端头形状。

当前在场景创建时找到每个出口接点对应的环路直段，只重画接点附近的小段。它们与宽出城路共用 painter，先统一画路缘、再统一铺路、最后按交点裁标线；该组使用平端头。其他路网继续使用原 painter 默认端头，不重建建筑或贡献布局。小镇出口同组铺设原有石路材质。

首次联合绘制仍沿用圆端头，放大检查发现环路短段两端产生额外鼓包；改用平端头后，相同四个位置的圆头、路缘横挡与标线穿口消失。没有靠移动接点或扩大一片灰色遮盖层隐藏问题。

## 环境与输入

macOS，Google Chrome 157.0.8103.39，Node v26.7.0，Playwright 1.62.1，1280×1000 headless，独立系统临时 Chrome 配置，实际 MV3 构建与真实扩展存储。

- 真实匿名访问 wxy、torvalds、octocat，贡献读取和解析走实际 GitHub；没有读取个人浏览器配置、Cookie 或 Token。
- 本机路线输入 `wxy=[torvalds,octocat,null,null]`；先把目标 torvalds 的配置设为无效字符串，确认 wxy 仍按自身设置展示和访问，证明不会为推断双向去解析目标配置。随后设置 `torvalds=[wxy,octocat,null,null]`、`octocat=[null,null,null,null]` 检查已有出口和临时返程。这些是明确的测试输入，不是对账号真实关系的断言。
- 本人编辑只用受控 `meta[name=user-login]=wxy`，年度贡献、存储与渲染器不替换。此项不冒充真实登录或私有权限验收。
- 八路输入为 torvalds、sindresorhus、antirez、jashkenas、octocat、yyx990803、tj、abcdefghijklmnopqrstuvwxyzabcdefghijklm。末尾 39 字符字符串只用于排版，不访问或声称账号存在。

## 可复现步骤

```sh
TASK_TMP=$(mktemp -d -t codeyears-exit-junctions)
node scripts/bake-direction-boards.mjs
npm run build -- --outDir "$TASK_TMP/build"
npm run build
```

Chrome MV3 方式沿用前轮：Playwright 指向本机 Chrome，排除默认 `--disable-extensions`，临时配置使用 `--enable-unsafe-extension-debugging`，browser 级 CDP `Extensions.loadUnpacked({path: buildPath})`。通过扩展 `options.html` 写入上述存储输入，语言设为 en。

1. 进入 wxy 城市，等读取结束和短填入完成，Fit view 后分别缩放四条路接点到 400%。源/目标点共用原路面多边形，比较修复前后的同一点位；查看四个方向的空牌。
2. 在两种地图记录主 Canvas 的 `fillText`、矩阵及 `measureText` 实际包络，触发一次缩放重绘。道路文字以箭头识别，按当前路面四边形判断所有字形角点在出城侧；空路不应产生文字或问号。
3. 按 A→B→C 行驶，确认 B 复用既有返回出口、C 提供临时牌；刷新 C 后回 B/A，并比较两城原数组。
4. 用受控本人身份通过空牌添加并保存，预置八槽；两种地图逐块右键核对 ID，再从可见额外路面拖动、点击去 octocat、返回并比较八槽数组。
