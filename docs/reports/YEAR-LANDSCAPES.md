## 实现与表现

- 每年独立底座，20 列×19 行日期位置；不把它声明为周历。按时间升序排列年份、年内日期；缺失/未来位置不生成建筑或地形面。
- City 使用实例化建筑，按贡献量调整高度、体量和相近绿色色阶；每五格留出街区间隔。年份标注在缩放与长历史下保持约 13 CSS 像素字高，避免被地形遮挡。
- Terrain 每个真实日期为一个带中心点的地形单元；中心高度来自该日 count 的对数映射，公共角点只做相邻日期的视觉插值。原始数量、年度合计与缓存均不修改。
- `createLandscape` 共用 renderer、相机、时间轴和年度底座/标签；`setView` 仅释放旧视图并构建新视图，保留播放位置、暂停意图和相机，不访问网络/缓存。只构建当前视图，不常驻两套几何。
- 高度、矩阵、颜色和地形法线提前计算；播放只改可见实例数或索引绘制范围。暂停/完成不续连续帧，交互按需单帧。
- Three.js 与两视图改为本地 `landscape.js` 按需加载；manifest 替换原 `city-preview.js` 资源声明，允许源仍仅 GitHub。权限、依赖、数据/身份/缓存策略不变。

## 本地示例实际显示

运行 `npm run preview:city`，打开 `http://127.0.0.1:4175/`。使用既有 `generateDays('regular')` 确定性样本，三年 2023–2025 为 1096 天/13729 次，二十年 2006–2025 为 7305 天/93171 次；页面明确标记示例。

实际查看三年 City、Terrain 和二十年两视图：年度底座分开，年份可辨认；没有变成一整块跨年方格。三年重播暂停在 2023-03-04（63/1096），切 Terrain 后仍为 63、按钮保持“继续”、Canvas 为 1；间隔后仍不推进，继续/跳过正常。切到二十年 Terrain 后可完整显示 7305/7305；最终 City 的二十年年份标签完整可读。

首次二十年视觉检查发现 Sprite 标注被底座/地形局部遮挡，改为注释层并复核；此后构建与受控 UI 绑定上列最终源码。浏览器背景标签曾发生工具调用超时，激活任务预览后恢复，未将其误报为产品检查通过或功能缺陷。

## 受控完整 UI 与生命周期

系统临时页面加载实际注入脚本与本地风景模块，只将当前 URL 边界适配为 GitHub 主页。虚构主页 octocat、访问者 alice，fetch/Chrome 存储为受控边界，其他解析、身份确认、缓存、历史组装、UI 和渲染为实际模块。页面包装 RAF/cancelRAF 及 WebGL buffer/texture 创建/删除并把计数显示到 DOM；不是性能测量，也不是实际 MV3 或真实身份切换验收。

年度输入复用 [多年份报告](MULTI-YEAR-CITY.md) 的生成规则：2023–2025 共 1096 天/2804，包含真实零值和闰日。临时编译只替换 `new URL(location.href)`，年度 fetch 根据 `from` 返回英文日期/数量/年度标题 HTML，身份 fetch 返回 alice 的完整 HTML；存储使用 Map 的 get/set/remove。通过实际 UI 执行下列路径。

| 路径 | 实际观察 |
| --- | --- |
| 初始未生成 | 无年度/身份请求、RAF、WebGL 或 Canvas |
| 生成 City 后暂停 | 年度顺序 2023/2024/2025，身份请求 6，缓存 3；18/1096、按钮“继续”；1 Canvas / 1 WebGL 上下文 |
| 暂停切 Terrain | 仍为 18/1096，暂停意图不变；年度和身份请求数不变，上下文仍为 1；单帧更新后 frames=10、pending=0，后续观察不变 |
| 三次 City↔Terrain 往返 | 请求/上下文/纹理数不增加；回到 Terrain 完成绘制时 buffer 计数回到同视图的 11、纹理仍 8；没有每次重建 WebGL |
| Terrain 继续/跳过 | 1096/1096，暂停按钮禁用，pending=0 |
| 重播中关闭风景 | Canvas 为 0、pending=0；frame=39 后保持不变，捕获 1 次 webglcontextlost |
| 直接生成 Terrain | 3 年全缓存，无新增年度请求；身份请求按既定策略到 12；单个新 Canvas，跳过到 1096/1096 |
| 关闭整个面板 | 面板/Canvas 为 0，原占位贡献日历仍为 1；累计上下文 2、丢失事件 2，frame=53 / pending=0，后续观察不变 |

资源计数只证明可观察调用与上下文生命周期，不等同于精确显存、JS 堆或长期资源预算。上下文丢失后，包装器仍保留先前创建的引擎内部句柄记录，不能用它们宣称显存为零或断言泄漏。本轮没有为理论极端时序增加防御、重试或新测试框架，也没有在实现后补写单元测试。
