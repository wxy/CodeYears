# 标定单元接入、街区与近景验证

日期：2026-10-31。实现提交：`ff6ea27`，分支 `codex/year-landscapes`，更新 PR #15，不合入。

## 范围与结果

22 款新透明单元与 3 款旧中高层的标定已接入真实 City；两个幼树变体复用单树源文件。运行目录合计 27 个 id / 25 个文件。双轴校正、地面包络居中、退让与平地映射同标定预览共用源码和 JSON，原 PNG 没有修改。季度交叉路插入额外空间，地块合并不越路；五年景观带沿用所选最早年份起分组。

用户实测的两个问题已复现：固定 5 倍上限限制多年全景的近看；整块灰白底面缺少内部连接。现在 City 上限为 `max(5,192/fitScale)`，目标使一个逻辑格的横向投影约 192 CSS 像素；Terrain 仍为 5 倍，切换时重新约束。底面改为绿地庭院、紧凑铺装、入户步道和沿合并地块边界连接的窄支路，不切开大建筑。

随后近看发现整张地面缓存放大会模糊。高倍视图改为可见范围的矢量道路与烘焙平地素材重画，结果缓存为视口大小；尺寸、缩放或平移变化才重建，镜头静止的生长过程复用。低倍仍使用整城地面缓存。以下是功能检查，**不是整体美术通过或性能预算验收**。

## 可复现输入与直接路径

普通展示：运行 `npm run preview:city`，访问 `http://127.0.0.1:4175/`；可选一年、三年、二十年与常规、稀疏、高密度，操作缩放、拖动、重播、暂停、跳过、重置和视图切换。

定向检查使用系统临时目录下的 Vite 页面，直接导入正式 `createLandscape`，1100×600 CSS 像素、DPR 上限 1.5。临时页面把规划摘要、请求/位图/帧计数和关闭结果写到可见 DOM，通过浏览器 UI 操作与读取；未把计数接口加入扩展。记录方法：`createImageBitmap`/`close` 统计源解码生命周期，`fetch` 统计素材请求，正式 draw 调用处统计帧和视图；规划检查成员索引的日期/行列、贡献合计与季度边界。

输入复用 `src/renderers/probe/data.ts`：2006-01-01 至 2025-12-31，种子 20060101，每日 `seed=(imul(seed,1664525)+1013904223)>>>0`。常规为 `seed%5===0?0:1+seed%30`，稀疏为 `seed%20===0?1+seed%40:0`，高密度为 `50+seed%151`。三年截取 2023–2025。专项输入在运行时生成 2024 年真实日期，替换 count：全零=0、树木=4、幼树=1、低层设施=6（仅最后一天=1000）、周一重复=周一12/其余0；部分年取 1 月 1 日至 3 月 15 日且 count=6。生成输入不留存。

## 缩放、播放与释放

- 二十年生成 5792 个数据地块。0.35、5、细节上限、重置四档的布局指纹均为 `2978872280`，素材请求数不变；上限在该窗口为 `22.29213483146067` 倍。指纹基于单元 id、比例、位置、占地及源日期索引，缩放不触发重新规划。
- 最终近景版本再次观察到相同 22.292 倍；拖动后平移量为 100 / 50 CSS 像素，街道和楼体一起移动。截图现场确认季度主路、边界窄路、庭院、建筑、草地均可近看，道路不再由低分辨率地面缓存放大。
- 已完成状态可从起点重播、继续后暂停。最终近景暂停在第 36/7305 天；后续读取 draw 计数保持 8。此前切换 Terrain 和返回 City 保持同一播放位置与一个可见画布，PNG 请求未增加；离开 Terrain 观察到对应 contextlost。City 高倍进入 Terrain 后倍率约束到 5。
- 常规二十年实际需要 17 个 id / 15 个文件，烘焙画布合计 1,017,841 像素、长边不超过 384；不是将全部候选一起解码。源位图在烘焙后已关闭；与初始三年共计 created=closed=56。City 单独运行时 WebGL 计数为 0。
- 关闭后二十年主机画布为 0，17 张烘焙画布尺寸全部为 0×0。素材失败分支将一个实际需要的 PNG 请求返回 503：显示“城市素材加载失败，请重新生成风景”，不显示成功画布；部分成功烘焙全部清零，累计 created=closed=80。重新生成三年恢复一个画布、100%，created=closed=106，没有页面未处理错误。
- 最后近景缓存补充后再次验证二十年近看、拖动、重播与暂停；缓存所有权与清零路径也经源码检查。没有把宿主画布移除等同于整个浏览器内存或 GPU 预算已通过。

## 真实 Chrome MV3

普通刷新 GitHub 个人主页，等原贡献日历出现后，从 CodeYears 弹窗主动打开，选择默认最近三年（2024–2026），生成、跳过到 100%，多次点击放大进入清晰近景。现场看到新住宅、树林、池塘、广场、绿地庭院和支路；新版说明文本存在，画布一个，GitHub 原生 `.js-yearly-contributions` 仍为一个。关闭风景后画布为零、原日历仍为一个，再生成成功。

本路径使用现有年度缓存并按原逻辑重新确认身份；没有在本报告保存真实逐日数量、年度贡献总数、缓存、凭证或页面响应，也没有重测全部数据请求/身份矩阵。此次普通页面刷新已能加载新构建，无需新增权限或改动扩展管理设置。浏览器控制连接发生过中断，恢复后完成上述路径；没有把控制工具错误算成产品通过或失败。
