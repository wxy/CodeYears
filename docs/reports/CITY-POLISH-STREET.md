# 街道生活细节原型报告

日期：2026-11-08。固定起点 `5c6d2e60b3becdbb5900d98cb7478a1fbf9b6bba`，分支 `codex/city-polish-street-probe`。初始云端 checkout 是旧 `7fe7338`；取回 main 后从指定提交建分支。已读 AGENTS、产品、云端、数据隐私、性能、单元规范及最新桥梁/缩放报告。共享 src、主配置、锁文件、正式入口和他人文件未修改。

## 假设

正式城市已经有楼脚铺装、入口短接路和边界窄支路。本轮假设：在一个连贯街区把窄支路扩为克制的暖石步道、保留接缝，可能改善低层生活尺度；若高层/远景几乎不可见，则不值得全城推广。不是把已有入口短接路重新当作新增成果。

## 实际实现

只新增工程预览。首个合适片区取最多12列，沿完整建筑地块边界生成0.16格宽步道边缘，共享边去重、保留合并地块；两条半格接缝/边。用规范每边至少0.1格的标定退让检查包络，额外留0.01格；裁在片区内侧，保留外部街角。既有入口短接路和楼脚铺装随后绘制。没有加过街线、停车入口、站台、围栏或其他立体小物。

地面在规划时构造 Path2D，在 `createOrganicGround` 后、原有楼脚/平地/楼体之前画入原静态缓存；远近景继续共用正式缓存机制。没有最终画布布局补丁，没有移动或删除道路和楼体。原地块、indices、ISO定位、年度/季度道路、片区接路、路口、桥位/高度/入水关系都来自同一个未变场景。路名处于样板外的正式车行路面；候选裁剪在片区内部。水塘平地与楼体按正式顺序覆盖地面，不将步道漂在河道上。

候选切换只重建右侧工程视图，不重规划输入、解码PNG或改变相机；隐藏保留两个视图与素材，恢复原取景，关闭则dispose并清零。原型不增加持续定时器或RAF。未新增图片或提高任何素材尺寸预算；不需要生成精绘小物，未使用imagegen。左/右额外两份视图是工程比较开销，不建议正式入口保留双视图。

## 实际验证

Linux云端，Node24.19.0、npm11.9.0、Chromium154.0.8037.57，独立headless上下文；不使用真实GitHub登录或用户浏览器资料。Canvas结果只代表该云端环境，不作为本机GPU、功耗、真实登录或Edge验收。

通过 `npm ci`、`npm run check`、`npm run build -- --outDir /tmp/codeyears-street-production`、原型独立tsc、Vite预览构建与 `git diff --check`。预览JS83.29kB/gzip30.90kB；正式landscape114.07kB/gzip35.14，正式源码未改。未事后补单元测试；保留的是直接浏览器路径检查脚本。

五组输入非零成员覆盖唯一、数量合计守恒，候选规划前后整个plan的JSON相同。关闭候选后两侧Canvas逐像素一致。每组截图覆盖整体和近景，已逐项查看低层、高层、稀疏近景与多年整体的实际PNG画面；近景候选开启后与基线差异像素分别16837、2910、6908、2955、2421，均大于0（仅证明实际绘制发生，不等于观感改善）。没有浏览器脚本错误。

每组静止1.2秒：实际Canvas `drawImage`、`clearRect` 和RAF请求增量均0，视图draw调用计数亦不变。隐藏300ms后恢复：沿用同一实例/相机，候选地面paint计数不增加。释放后两个主画布尺寸均0×0，重新打开最后一组成功且合计不变。自动驱动覆盖五组、候选开关、近景、隐藏恢复、关闭和重新打开；二十年输入滚轮上下限另验证为50%和2000%；鼠标拖动的主观手感、完整后台矩阵不在本轮验收范围。

首轮曾误把素材nativeWidth当成实际楼脚包络，结果候选所有边被排除；该次截图没有变化，不能算成果。检查后采用正式规范的标定退让，最终复跑才得到上面的像素差异。另一次开发热更新干扰静止计数，已废弃该次结果并在稳定源码重跑。原始合成输入只在浏览器内生成，截图、日志、临时构建与浏览器上下文记录后清理，不入Git。

## 视觉取舍

- 低层：近景增加细窄连续暖石边与接缝，入口附近更完整，但与现有铺装色差小，提升温和。
- 高层：楼体遮挡大部分地面，效果很弱；靠扩大步道宽度换可见度会侵占楼间退让，不建议这样做。
- 稀疏：保留空白，细节仍可见；现有城市铺装本身已有格状纹理，继续加线容易强化棋盘感。没有把无人连接的草地另铺成车行断头路。
- 多年整体：差异几乎退到背景，不明显增加视觉杂乱，也没有显著提高整体生活感。不能用“看起来没变杂乱”推断值得全城采用。

本样板未新造门的位置，只复用已有入口短接路；地块级边界不等于真实院墙或建筑门向。标定规范的退让也不是逐张PNG美术复核；所有入口朝向和细部遮挡仍需用户近看接受。

## 成本

新增PNG0、源图0、请求0、运行楼体尺寸变化0。每次地面缓存重建额外一个clip、一次合并fill、一次接缝stroke；静止无额外提交。候选规划一次扫描全城建筑包络，故本样板不等于常数成本：最终单次规划样本低层6.8ms、高层1.8ms、稀疏0.9ms、六年4.2ms、二十年10.3ms；受云端调度影响，仅是观测，不作性能增减或硬件预算结论。边界数量限制在12列样板，不把此方案直接复制到20年每个片区。

## 建议与未验收范围

**建议继续局部比较，暂不默认采用。** 保留可运行入口，作为低层街区备选；高层和整体收益不足，不值得先铺全城。若用户喜欢，最小接入仅需在既有静态地面回调插入该局部函数，默认仍需显式选择；不改道路、素材和数据框架。进一步方向应先比较一个真实必要的过街位置或准确入口，而不是再堆一批小物。

未验收：真实GitHub贡献/登录/身份、MV3页面集成、Edge、实际目标设备内存/GPU/功耗、完整20年性能预算、缩放键盘路径、所有素材实际门向与用户美术接受。用户最终接受前不合入、不发布、不推送main。
