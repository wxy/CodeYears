## 实际实现与比例核对

| id | 实际楼身参考高度 | W / D 每侧退让 |
| --- | ---: | --- |
| apartment-h2-a / b | 2.000 / 2.000H | 0.172 / 0.192；0.166 / 0.200 |
| office-h3-a / b | 3.000 / **2.800H** | 0.103 / 0.177；0.100 / 0.167 |

## 构建与方法

本机 macOS、Apple M1，使用已有锁定依赖、Chrome 156 与用户现成登录会话；未安装软件、改权限或登录。按素材装载/选择和地面交互风险验证，不重跑身份矩阵或完整性能硬件矩阵。

- `npm run check`、`npx tsc --noEmit -p probes/city/tsconfig.json`、`npx tsc --noEmit -p probes/city-units/tsconfig.json` 通过。
- 组合源码执行 `npm run build -- --outDir <任务临时目录>/dist` 通过；组合 `city-view.ts` SHA-256 为 `31f3dfa077a496ae2f391d21af516edf462bec65fb871a1da80728c7e0193e47`。未修改 manifest、依赖、锁文件、数据和缓存模块。恢复不含 #23 的本地堆叠源码后，再构建到 `<任务临时目录>/local-dist` 通过，landscape.js 76.00 kB / gzip 22.97 kB；此产物不覆盖项目内的组合预览 dist。
- 本地临时 Vite 服务 4183 直接引用正式预览和渲染模块。`enforce: pre` 的临时 transform 将场景摘要写入可见 output，给 Canvas 增加绘制次数 DOM 属性，并在 dispose 后输出画布/地面缓存尺寸与静态命令数。浏览器只通过现有控件操作并读取 DOM；这些插桩、配置与输入不进入正式源码或 Git。
- 另用 4184 启动正式 `probes/city-units/vite.config.ts`：28/28 加载，逐一选择六个 id，浏览器显示的高度/双轴/中心/退让与上表一致，检查共同地面拼接与原图/标定图。

常规示例很少覆盖 H1 大地块，额外用一次性视觉输入检查各组合：保留正式生成器的日期序列，在过滤年份前按零基日序 i 将 count 设为 `[0,1,4,6,9,18,40][(floor(i/21)+floor((i%7)/3))%7]`。这是受控视觉输入，不是真实贡献或正式产品映射。2024 可见六张新单格变体、H1 住宅/警消/总站、树木平地，以及 H1×2/H2×2 两种复用；两种 2×2 复用各有 A/B。未要求这组输入覆盖体育场/总站的全部随机候选，#22 的八组合选择检查已单独覆盖双候选。

现场检查浅深背景、三年/二十年全景、季度路口、三条五年公园带、细节上限、鼠标平移和重置。新楼体、地面与道路主边一致，造型/材质有区别，保留逻辑留距。近景可看见入口、玻璃/砖石立面与庭院步道；公园、池塘与地面在近远景保持顺序。整体最终美术接受仍留给用户，不把个人判断写成用户已确认。
