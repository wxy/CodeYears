# 接入前透视复核

日期：2026-11-11。范围限定为小镇建筑、设施和生活组件的离线校准，不推进主线合入或商店发布。

## 修正校准依据

初轮 `TOWN-CALIBRATION.md` 从同一组左/前/右包络点推导相机方向，再检查这些方向是否成为 `+0.5/-0.5`。这能验证变换计算，但不能独立证明可见墙脚、门楣和檐边已经对齐。初轮“主轴已统一”的表述按这个范围理解，不能当作独立构件验收。

本轮将两件事分开：

- `ground` 只描述保守的接地包络，决定居中和等比适配；不是隐藏基础的物理测量。
- `axes` 记录可辨认的水平构件方向，优先用于计算相机变换。`axisBasis` 区分直接量测和共享构造推定。
- `checkAxes` 是没有参与方向计算的可见边线，报告实际残差；`checkVerticals` 检查可靠柱边或门框。短线条的手工端点存在像素误差，不把数学精确拟合等同于画面无误差。
- 圆形水平基座按可见椭圆归一到 2:1；传送门竖直圆环不作为地面圆。人物、动物和花树只检查接触点和尺度，不伪造双轴。

同一幢建筑的同向水平边应一致。农场各幢建筑可能有意改变朝向，不能仅凭两条 D 方向不同就判定相机错误；是否能共享同一相机，需要每幢成对的水平正交方向证据。无法可靠辨认的构件保留推定或待复核状态。

## 复现

```sh
node --check probes/fantasy-city/project-sprites.js
node --check scripts/bake-town-assets.mjs
node scripts/bake-town-assets.mjs \
  --outDir "$TASK_TMP/calibrated" \
  --catalog "$TASK_TMP/calibrated.json" \
  --board "$TASK_TMP/board.png" \
  --proof "$TASK_TMP/proof.json"
```

`proof` 保留每个原始帧的依据、变换、独立边线角残差、竖边残差和人物参考结果。运行包只装载预烘焙 PNG，不在用户浏览时执行这些量测。

## 本轮准入与边界

- 保留 **41 张运行 PNG**（含 6 个镜像），合计 **4,568,403 字节**，长边均不超过 384。5 张原始图集不变。
- `forms-5/6/8` 不再分发：旧 U 形与宽庄园候选的基础被遮挡、证据不足；复合农场各幢朝向与相机关系也未充分确定。原图、测线与排除理由保留，`runtime:false` 只停止烘焙。替换运行目录时同时移除旧的三个文件，不留下未引用 PNG。
- `life-6` 集市的硬边接近正面，校到地图角度后过窄，也不准入首版；公共设施选择器继续使用魔法井、长椅、泉台、传送门与符文灯。
- 当前选择器已用 `magic-4/5` 承担行会/学院形态。较低强度的矩形农场改由 `forms-7-x` 连体畜舍与 `cottages-1` 农舍共同组成；两栋仍属于同一 parcel，沿用院落、作物、居民、动物及入户路，不增加贡献数量或成员日。
- 经典素材的完整依据见 [独立方向记录](CLASSIC-VISIBLE-AXES.md)。8 个小屋的 W 仍是共享构造推定；5 个水平圆基座均因遮挡保留人工推定，不声称取得了完整圆的独立量测。没有引入尚无可靠输入的另一套圆面参考字段。
- 5 条没有参与计算的经典建筑短边，映射后方向残差约 **0.66–1.70°**；两条标注长立柱仍竖直。这只是有限可见边线的实际结果，端点误差约 ±2–3 源像素，不能按小数位数宣称高精度或全构件通过。`forms-7` 穿过干草开口的旧长线已撤回，不计入这些结果。
- 人物、动物、花树与自然装饰仅作落点/尺度复核。六个魔法建筑的可见人物参考没有超过原型单位上限；这不是所有居民的摄影测量。独立审图复看当时的 42 张板后，进一步排除过窄的集市；其余 41 张没有新增明显倾斜、脱地或错误扭曲。

内置图像工具曾针对旧完整农场生成新候选，仍未取得足够证据，未采用或覆盖原图。完整提示词及取舍见 [重画试验](FARM-PERSPECTIVE-TRIAL.md)。

## 实际验证

环境：macOS、本机 Chrome 157.0.8103.39、Node v26.7.0。以 PR #78 的 `86e7538` 为隔离基线，仅覆盖本轮校准、运行资源和农场组合，未混入并行的手动道路任务。

1. 初轮 45 张 PNG 重烘焙，与该基线运行文件逐一字节一致，作为前后比较起点。
2. 最终 41 张完整解码，RGBA、透明留边、非空轮廓、有限元数据、实际接地跨度不超过预留、6 个镜像尺寸互换均通过。向输出目录放回4个被排除的旧PNG再烘焙，生成器准确移除这4个文件，其余41张及目录哈希不变；不会删除原始图集或其他输出。目录 SHA-256：`83d122701a3e5b4954679bbad80dfb46668e9e2356bfb73691fbc71d25eb7abd`。
3. `npm run build`（包含 `tsc --noEmit`）通过，构建目录实际分发 41 张 PNG、4,568,403 字节，集合与目录完全一致。依赖沿用已锁定安装，未更改依赖或重复安装。
4. 实际 `loadTownImages → createCityView` 浏览器路径：解码/绘制/Alpha 命中 **41/41**，同一帧再次调用 draw 没有新增建筑绘制；6 个镜像的投影包络、尺寸与透明图反射对应。透明图反射差约 0.00011%–0.23815%，包含抗锯齿与像素取整，不宣称逐像素完全相同。
5. 实际 `planTownScene → loadTownImages → createCityView`：2×2 / 3×2 / 2×3 农场均有两个实体，共用原 parcel；4/6/6 个日期与 12/18/18 次贡献守恒。声明接地矩形互斥且在地块内，两栋建筑实际 Alpha 命中均返回原成员日期。另以56日公共空间输入得到2处实际公共设施（魔法井、长椅），没有集市引用，全部场景资源键可装载。
6. 41 个解码 ImageBitmap 全部关闭；视图和图片释放后，记录到的 Canvas 尺寸全部归零。以上为这次实际路径，不外推内存、显存、FPS 或功耗预算。

整组运行 PNG 指纹：按文件名排序，为每个文件求 SHA-256，序列化为 `[[filename,sha256],...]` 后再求 SHA-256，结果 `9459d9806f147dd8f23d4411954f3061d7554355f21dd0e8060c0aeaef0a0256`。

### 浏览器复核的可重复输入与操作

使用本机一次性 Vite 页面直接导入 `town-assets.ts`、`town-layout.ts`、`city-view.ts`、`closeCityImages`，提供真实随包 PNG；不替换这些实现。全量组件按目录顺序摆在 8 列、每格 6×6 的技术网格，每个素材 factor=1、在格内居中。视口 3200×2300、DPR=1、zoom=1.05、pan=0、浅色；`draw(1)` 后按 3px、必要时 1px 遍历真实 `buildingAt`，确认 41 个索引均可命中，再重复同帧观察绘制计数。

农场输入从 UTC 2024-01-01（星期一）开始，形状 `(w,d)` 分别取 `(2,2)/(3,2)/(2,3)`，成员日为 `base + (row*7+column)*86400000`，每个已提供日 count=3，其他日期不补零。调用 `planTownScene(days,[2024])`，检查两个实体、共享成员和矩形边界；以正式 `createTownGround(plan)` 绘制并逐实体验证 Alpha 命中。公共空间输入为2024-01-01起连续56日，`i%4===0` 的日期 count=0，其余 count=3；检查选中设施只来自当前四类目录。最后 `view.dispose()`、`closeCityImages()`，检查实际位图关闭与画布归零。

该路径为技术输入，没有读取新的 GitHub 数据或登录资料。本轮不重复旧 UI 全矩阵，也不把上述结果当作真实登录 MV3、Edge 或完整性能验收。

## 图与留存

对照图和完整组件板是用户可复看的正式设计交付，仅存本机可视化目录；不含真实贡献数据，不加入 Git。它们展示的是统一网格上的当前观感，圆基座推定、隐藏接触面、每个屋檐/门洞和复杂建筑的全部局部朝向仍不在完整独立验收范围。

一次性页面、脚本、结果 JSON、日志、浏览器配置、基线/中间烘焙、测试截图和构建在记录后清理，仅保留正式源码、标注、产品 PNG、提示词与本报告。主线未合入、商店未发布。
