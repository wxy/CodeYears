# 西欧魔法小镇：圆形建筑、居民与公共空间原型

日期：2026-11-11。状态：**独立本机原型已渲染并检查**。本报告只记录设计原型；正式扩展新地图类型的实现与验收另行记录，不能把这里的 PNG 或 headless 原型结果当作扩展验收。

## 本轮设计

- 保留七列日期网格、相近贡献矩形与边界道路，圆形观星台和法师工坊的外观仍受矩形地块约束，不改成互相拼接的圆形地块。
- 保留普通乡间长屋和工坊长厅，在较高档长条区域中稳定选择约三分之一魔法温室；较方正区域采用炼金庄园、魔法行会或宽侧翼学院。建筑用途是幻想美术，不声称已知道贡献活动类型。
- 每个贡献建筑单元配置门前居民组；新原画中还可见观测者、炼金学徒或授课人物。农场增加家畜，部分已知零日布置花树与动物。
- 公共空间包括集市、长椅、泉台、魔力井、传送门和符文路灯。公共设施只选已知零贡献日期，且须邻接贡献建筑、至少一条格边已有公共道路；每四周桶最多一处。格内小路将设施接到原边界路网。
- 人物、动物、设施与花树不表示贡献者人数、工时、实际人口或额外贡献，也不能从贡献数量推断项目。

三年总览实际提交 270 个建筑单元、270 个居民组、17 个家畜/动物组、99 棵花树、30 处公共设施和 30 盏符文路灯。组内人数和动物数来自素材构图，没有另作人口计量。

## 透视问题与修订

首轮实绘确认：部分源图的地面边比道路更平，单纯以原落脚点摆放会产生透视不一致。原型现按人工标注的可见地面轴做保持竖边垂直的方向校正，使两条主边斜率为 `+0.5` 与 `−0.5`；圆形底座映射到同一平面的 2:1 椭圆。

只做这个变换又暴露出第二个问题：第一版温室和 U 形行会会被纵向拉成高楼。为此使用内置图像工具重画通用素材，将六类魔法建筑改为低矮多开间、相连侧翼和较深庭院，并减小原画人物。保留原图，重画候选存为 [magic-town-v2.png](magic-town-v2.png)，完整修订提示词见 [MAGIC-PERSPECTIVE-EDIT-PROMPT.md](MAGIC-PERSPECTIVE-EDIT-PROMPT.md)。没有向图像工具发送真实贡献数据。

校准后选择混合来源：圆形小屋与观星台继续使用较紧凑的第一版，其余魔法建筑和设施使用第二版；来源由 [magic-town-v2.json](magic-town-v2.json) 的逐项 `source` 指定。可见人物或门洞的初标参考作为高度上限，避免方向矫正后人尺度失控。最终实图中 U 形行会为低矮侧翼围合庭院，圆形小屋和居民仍可辨认。

这些标注是原型地面包络与人尺度参考，不是恢复了隐藏的真实三维地面。通过主轴数学检查也不代表每个屋檐、窗沿或人物像素均已严格校准；精确 Alpha 遮挡与门洞对齐仍待后续验收。

## 原型直接路径验证与复现

环境为本机 macOS、Chrome 157.0.8103.39 headless、Node v26.7.0、Python 3.14.6。公开页获取与日期/tooltip 解析方法沿用 [前轮试算](../2026-11-10/REAL-PROFILE-TRIAL.md)，增加“完整源年合计先核对、历史截止日后再筛选”的步骤。输入 JSON 和原始 HTML 只在任务临时目录。

本机 HTTP 服务仅监听 `127.0.0.1`，提供经过校验的数据、通用 PNG/JSON 和四个原型脚本。按 [原型调用说明](../../../../probes/fantasy-city/README.md) 加载规划器、投影器及绘图器，并使用 `canvas.toBlob(..., 'image/png')` 导出。Chrome 调用为：

```sh
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --no-first-run --no-default-browser-check \
  --disable-background-networking --disable-sync --hide-scrollbars \
  --force-device-scale-factor=1 --virtual-time-budget=10000 \
  --user-data-dir="$TASK_TMP/prototype-browser-profile" --dump-dom \
  "http://127.0.0.1:$TASK_PORT/"

node --check probes/fantasy-city/plan-courtyards.js
node --check probes/fantasy-city/plan-building-forms.js
node --check probes/fantasy-city/project-sprites.js
node --check probes/fantasy-city/render.js
git diff --check
```

浏览器在真实输入上实际通过：

1. 第一阶段原矩形完整归属、无孔洞和重复；每个正贡献日期覆盖一次，零值/未来/未知日期不生成贡献建筑，宽度不超过七列，合计守恒。
2. 491 段边界路网不穿过同一庭院内部，所有院门连通西侧主路。
3. 37 个具有投影元数据的素材按标注主轴或圆形底座校正；主轴达到 `±0.5`，圆形底座宽高比为 2。声明建筑包络留在地块内，前方保留通路。
4. 总览与三个近景实际建筑素材提交次数分别为 270、15、56、17，与所选地块数相同；居民组提交次数分别相同。公共设施均落在输入中真实存在的零值日期，且连接原道路边。
5. 四张地图与一张组织示意图完整解码并实际查看。首轮发现过高楼体后重画并复验受影响图，再输出最终取景；没有用反复重跑掩盖问题。

本任务原型只使用一次静态绘制，不新增单元测试，不将它当作正式扩展的交互、缓存、身份矩阵或性能验证。主代理完成同输入的扩展验证后，已确认无相关浏览器进程并统一清理原始 HTML、逐日/地块数组、原型页面、浏览器配置/日志和分析脚本；只长期保留报告与通用设计素材，最终用户图留本机。
