## 真实数据如何成为画面

1. 继续使用 [ADAPTIVE-PLAN.md](ADAPTIVE-PLAN.md) 的七列日期网格与矩形试算，条件为 `max−min <= max(2, 25%×均值)`。零值保留自然地面，不生成房屋；未知及未到日期不补零。
2. 每个矩形对应一栋房屋，位置来自日期坐标；总览保留各年相同世界尺度，年份间装饰走廊不代表额外日期。
3. 按区域均值的 1–2、3–5、6–19、20–49、50+ 示意档位，选择茅屋/民居、半木构住宅、工坊、行会、精致奇幻工坊各两种变体。变体按年份和地块位置稳定选择，高度不编码贡献等级。这些外观档位尚未被确定为古代主题产品规则。
4. 多格地块仍保留整块真实占地，以庭院、围栏和铺装表达；建筑主体不随占地整体拉伸。当前还没有制作长屋等匹配各种矩形尺寸的专用建筑。
5. 使用同一等轴投影、透明图集落脚点与前后顺序，在本机 Canvas 2D 绘制并直接导出 PNG；没有将真实贡献或地块布局提交给图像模型重画。

## 验证与复现

本次新增独立原型绘图代码，因此不仅核对文档，还在真实本机 Chrome headless 中执行从公开数据到最终 PNG 的直接路径。没有修改正式扩展的控制流、资源装载、工程配置、权限或版本，因此不运行无关扩展构建与回归；不新增单元测试。

静态检查：

```sh
node --check probes/fantasy-city/render.js
git diff --check
```

数据获取与解析遵循 [真实公开试算报告](REAL-PROFILE-TRIAL.md) 的公开 GET、英文 tooltip、日期覆盖、年度合计和星期一锚点规则。旧年度校验值匹配，当年变化明确记录。重新核对每个非零日期恰好归属一个矩形、矩形宽不超过七列、成员贡献守恒。

临时本机服务只绑定 `127.0.0.1`，提供已经过校验的数据、图集、地面和原型代码。使用 Google Chrome 的独立临时 `user-data-dir`、`--headless=new`、`--disable-background-networking`、`--disable-sync`、`--dump-dom` 执行本地页面。页面依次调用原型的总览与近景配置，并通过 `canvas.toBlob(..., 'image/png')` 将结果写到本机输出目录。两种调用参数见原型 README。

浏览器返回的计数来自实际房屋 `drawImage` 分支，不仅是输入数组长度：总览为 315，近景为 67，与各自选中的源地块数一致。环境图块单独计数，不充当房屋。两张 PNG 完整解码并实际查看，图集 Alpha 范围为 0–255、十二格均可独立读取。发现首版近景边缘截断后，只重渲染直接受影响的近景；最终图已查看。

临时 HTML、逐日数组、地块 JSON、浏览器页面/配置/日志、服务及分析脚本在报告完成后清理，不进入 Git。项目仅保留通用图集、标定、独立原型源码、提示词与报告；真实结果图保存在用户本机可视化目录。

## 当前可判断的效果与限制

真实数据形成了 2024 的零散聚落、2025 的几段街区和 2026 较密集的连续街区；不同房屋形态可以表达均值差异。当前严格合并参数仍以小地块为主，所以画面没有人为插入大片村庄。

此原型可以评估真实数据的整体观感，但素材的世界尺寸、精确屋檐包络、遮挡和完整多格楼型尚未达到正式接入标准。道路、桥和河流是静态装饰，未做正式路网和入口可达性验收。没有验证真实登录 MV3、Edge、真机帧率、显存、内存或功耗预算，不据此宣称正式主题已实现或可发布。
