# 真实贡献渲染修订：庭院、农场与连接小路

日期：2026-11-10。状态：**本机设计原型已渲染并验证，未接入正式扩展**。本轮回应房屋凌乱、间距不足，以及相近区域应合并成更大院落的反馈。保留 [初版真实渲染记录](REAL-RENDER.md) 和输出，不覆盖历史对照；初版绘图代码为提交 `4a3a3fb`。

## 原因与修改

代码中没有房屋位置的随机抖动。旧版把主屋放在不同宽高地块的中心，导致半格错位；房屋横向包络接近单格投影宽度的八成，地块边缘仅退让 0.07 世界单位，且没有院内连接路。每块单独选择外观变体与较强的草地纹理又加重了杂乱感。这是布局及制图规则的问题，不能由此判断真实日期坐标有误。

本轮不改素材图集与标定，调整以下规则：

- 日期格间距从 1 增至 1.7 世界单位，房屋的物理绘制尺寸保持原值，给院落和公共小路留空间。主屋在地块后侧使用固定偏移，不再随地块宽高居中；去除绘制层额外的 0.34 整体坐标偏移，让主屋与围栏共用同一坐标约定。
- 地块四周留约 0.17–0.18 的边缘，绘制围栏或低矮石墙、前院门、草坪、门前小块铺装及入户路。同一星期列组采用稳定外观变体，减少逐块跳色。
- 相近原地块可组合成更大的完整矩形，每个最终庭院只绘制一栋主屋。低两档且面积至少三格时绘制菜畦；其他多格庭院绘制花圃。空余面积由土地和院落陈设表达，房屋不拉伸，也不按贡献增高。
- 公共小路走地块边界，从每个前院门接到本年度西侧主路；同一庭院内部的格线禁止成为公共道路。院内入户路另行绘制，院门处保留围栏缺口。

最终近景已实际查看：同一排的房屋朝向和后侧位置一致，房屋之间可以辨认围栏与路径，大地块可见一栋主屋配花园或菜畦。素材落脚点本身仍是初步标定，不能把此次布局改善当作完整美术包络验收。

## 同一输入的两阶段合并

第一阶段沿用原型的日贡献相近矩形，条件为 `max−min <= max(2, 0.25×均值)`。第二阶段新增的候选条件是：**相邻完整原矩形的均值处于同一视觉繁荣档，并且合起来仍是无孔洞矩形**。

繁荣档为 `≤2`、`(2,5]`、`(5,19]`、`(19,49]`、`>49`。第二阶段从所有候选按面积、紧凑度、行、列顺序选择互斥矩形；不切原地块、不吞零值或未知日期、不跨年。最终均值由所有成员日贡献合计除以实际日数计算，不是几个原地块均值的简单平均。实现见 [plan-courtyards.js](../../../../probes/fantasy-city/plan-courtyards.js)。

**同档是本轮试算采用的相近条件，不代表每天仍满足第一阶段的极差约束，也尚未成为正式产品规则。** 第一阶段原地块不拆分，可能限制第二阶段能形成的矩形数量；本轮没有尝试求全局最少地块，也没有把 L 形改成不规则占地。

## 验证与复现

直接受影响的是独立原型的规划与绘制，因此验证本机真实数据到最终 PNG 的完整路径。不修改正式扩展入口、构建、权限、资源或版本，不执行无关扩展回归，不新增隔离单元测试。

静态命令：

```sh
node --check probes/fantasy-city/plan-courtyards.js
node --check probes/fantasy-city/render.js
git diff --check
```

浏览器环境为本机 macOS Google Chrome 157.0.8103.39 headless，使用独立临时 `user-data-dir`；静态检查为 Node v26.7.0，本机服务与解析使用 Python 3.14.6。临时 HTTP 服务只监听 `127.0.0.1`，提供已经过入口校验的逐日数据、原地块、规划代码、绘图代码及原有素材。页面依次加载规划器、渲染器，按 [原型 README](../../../../probes/fantasy-city/README.md) 的三个配置调用并使用 `canvas.toBlob(..., 'image/png')` 导出。

```sh

  --headless=new --no-first-run --no-default-browser-check \
  --disable-background-networking --disable-sync --hide-scrollbars \
```

同一浏览器页面在真实输入上断言并通过：

1. 每个第一阶段矩形恰好属于一个最终庭院，成员完整、同档，无切割或孔洞；每个活跃日期恰好被覆盖一次，零值、未来和未知日期不被占用，宽度不超过七列。
2. 各年最终庭院贡献合计分别为 440、1,319、5,950；重新加权后的均值仍位于对应档位。
3. 每段公共小路连接相邻整数网格顶点，不能让两侧属于同一庭院；每个院门在实际输出的路网中都能到达西侧主路。三个年度分别有 104、152、235 段去重公共边，共 491 段。
4. 实际房屋 `drawImage` 分支计数分别为 270、56、17，等于各取景的庭院数；这些房屋均与输出画幅相交。近景筛选整年规划，不重新切块。所有 PNG 完整解码，三张最终图均实际查看。

首轮查看发现大庭院铺装过满，因此只调整受影响的院内地面、种植区和年份标题，随后重渲染并验证三个最终取景。没有为获得通过而重复运行相同失败检查。

服务已关闭；公开 HTML、逐日 JSON、临时浏览器页面、配置、日志与分析脚本在报告完成后清理。Git 仅保留通用原型代码和说明，不提交真实逐日数据或结果图。
